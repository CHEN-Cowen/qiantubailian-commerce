# 给开发软件的总提示词

你正在接手“千图百炼”AI 商品图生成与更新工具。请基于当前源码增量开发，使商品图评审和修订 Skills 真正进入产品，并复用现有任务系统形成受控循环。

## 先检查，再实施

读取项目指令文件、README、package.json、`docs/PRD-商品视觉AI工作流升级开发方案.md`，以及本目录的阶段任务和运行时契约。核查相关源码及调用方，区分已有实现、尚未接入、仅模拟验证和真实服务已验收。以实际代码纠正文档偏差，并记录依据。

保留工作区已有修改。先查看版本状态与可用运行环境；不能将其他人的未提交修改归入本阶段成果。无需先提交、切换分支或清理工作区。

没有指定阶段时执行阶段 0：交付现状差距、样本标注表与基线运行记录，并完成不依赖真实接口的准备工作。已指定阶段时，在完成必要核查后直接实施该阶段，不停留在计划。按阶段依赖推进，每阶段交付后由用户决定下一阶段；不擅自一次性重写全项目。

## 实现约束

- 主任务生命周期复用 `src/jobs.mjs`；质量门槛复用 `src/m07.mjs`，版本与修订复用 `src/m08.mjs`。新增复杂逻辑拆成小模块，不另建重复调度器。
- 使用当前项目的运行方式、依赖和存储模式。先查现有工具再决定是否添加依赖，不把数据库迁移或新框架作为前置条件。
- 生成事实来自已确认商品资料；视觉识别和 OCR 只提供候选或证据。包装、实物规格、套装数量发生变化时沿用现有素材与复核规则。
- 保留租户隔离、CSRF、额度预留与释放、成品计费、幂等、取消、未知响应恢复和导出有效性检查。模型内部成本单独记录，不新增隐藏扣点。
- 模型报告不能覆盖确定性失败，缺失检查、超时、无效输出不能当作通过；人工裁决沿用当前代码的可裁决范围。
- 先接评审并展示结果，再接修订建议与人工执行，最后开放有限自动执行。规则工具优先，模型只在白名单内建议动作。
- 能力以真实 Provider 为准。无掩码能力时不启用严格局部编辑；图生图不是局部编辑的证明。
- 密钥通过服务端环境配置提供。模型输出的路径、URL、ID、动作与参数都不直接信任。

## Skill 的实际接入

使用 `skills/commerce-image-reviewer/` 和 `skills/commerce-image-refiner/`。原小说场景 Skills 保持原用途。

遵循 `RUNTIME-CONTRACT.md` 和 `runtime/ASSEMBLY.md`。服务端必须实际加载受信任规则、发送真实图像、调用模型、校验 JSON 和业务语义、绑定版本并保存报告。新增 SKILL.md 或模拟返回正确 JSON 均不代表产品接入完成。

本包 Schema 是供应商无关的应用契约；如接口仅支持 JSON Schema 子集，可做等价接口适配，但服务端保留完整验证，不能删掉失败分支。尚未确定接口时定义最小 Adapter 和确定性 mock，不虚构可用供应商配置。

## 验证与交付

先记录相关基线，再做增量修改。运行与改动相匹配的契约、权限、版本、预算及恢复测试；集成完成后运行项目要求的检查与全量回归。逐项记录命令、运行环境、结果及已有失败；不反复运行与改动无关的检查。

按 `ACCEPTANCE-CASES.md` 验证异常与业务场景。真实视觉效果使用人工标注样本，模拟服务只验证流程。未授权调用真实计费接口时，完成其余工作并说明具体需要的测试和预估成本；不得把等待授权写成已验收。

每阶段交付：

1. 实际完成的功能、改动文件与用户可见变化。
2. 实际测试结果、真实服务状态及未验证项。
3. 配置和运行方法，不含密钥。
4. 问题、限制、下一阶段入口。
5. 更新本目录 `IMPLEMENTATION-LOG.md`，保证下一位开发者能继续。

普通可逆实现无需重复确认；涉及付费外部调用、发布、数据破坏或缺少必要业务判断时先提出具体事项。遇到局部阻塞继续完成不依赖它的工作。最终回复明确区分“规则材料”“代码接入”“模拟验证”“真实效果验证”。

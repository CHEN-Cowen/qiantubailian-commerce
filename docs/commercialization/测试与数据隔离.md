# 千图百炼 · 测试与数据隔离

## 1. 目录约定

| 目录 | 用途 | 是否入库 |
| --- | --- | --- |
| `runtime/` | 默认运行数据（projects/runs/credits/blobs/backups） | 否（gitignore） |
| 临时目录（`os.tmpdir()` 下 `mkdtemp`） | 所有自动化测试的数据目录 | 否 |
| `docs/commercialization/` | 进度、模块清单、依赖与验收记录 | 是 |
| `frontend/assets/demo/` | 演示图片素材（真实模型生成样例，已注明来源） | 是 |

## 2. 自动化测试隔离规则

1. 每个用例通过 `mkdtemp` 创建独立目录，用例结束 `rm -rf`；不得读写 `runtime/`。
2. 服务实例使用 `port: 0` 随机端口，测试结束 `app.close()` 并 `drain()` 写队列。
3. 新增身份/账本/支付用例时必须使用独立租户与独立账户，不复用演示租户数据。
4. 涉及真实外部服务的用例一律跳过并显式输出跳过原因，不计为通过。
5. 备份/恢复用例只在临时目录内构造，不触碰真实用户数据。

## 3. 数据与密钥

- 仓库不保存任何密钥、证书、私钥或个人收款码。
- `.env` 被 gitignore；只提交 `.env.example` 的变量名与安全默认值。
- 演示数据与真实账户数据分离：`/api/demo/*` 只读静态示例，真实首页/作品库/余额/搜索读取登录账户数据。

## 4. 迁移与回滚

- 存储为版本化 JSON（`schema_version`）。结构变更必须同时提供：
  - 变更前备份（`/api/backups` 或直接复制 `runtime/`）；
  - 迁移脚本与迁移后核对（表键、租户归属、账本余额一致性）；
  - 回滚方式（保留旧 `data.json` 与 blobs 副本）。
- 任何账本结构变更先在临时目录演练，再在真实环境执行。

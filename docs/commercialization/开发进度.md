## 4. R09 范围与验收

### 范围

**账本扩展**（`src/credits.mjs`）：
- `LEDGER_TYPES` 新增 `'revoke'` 类型：订单退款回收，从 `available` 扣除，不影响 `consumed`（已交付商品对应额度不可回收）
- 新增 `refundableCreditsForOrder(data, tenantId, orderId)`：按 `lot.source_order_id === orderId` 过滤批次，求和 `lotAvailable(lot)`（已用/已预留不可退）

**订单结算 grant 关联订单**（`src/api.mjs`）：
- 所有订单结算的 grant 调用（免单、零金额、demo settle、微信回调、查单同步）均补充 `lot: { order_id: order.id }`，使批次可追溯到来源订单

**退款路由**（`src/api.mjs::refundBillingOrderRoute`）：
- 先读订单判断 `real_money`，演示订单直接 `ORDER_NOT_REAL_MONEY`（不暴露系统退款能力状态）
- 已退款订单（`refund_status==='success'` 或 `status==='refunded'`）优先拦截 `ORDER_ALREADY_REFUNDED`
- 可退额度 = `refundableCreditsForOrder`，`<=0` 抛 `NO_REFUNDABLE_CREDITS`
- 退款金额 = `min(price_cents, round(price_cents * refundableCredits / order.credits))`
- 退款单号 `out_refund_no` 同一订单固定（`RF_${order.id.slice(-16)}`），失败可重试
- Provider 退款失败：记录 `refund_status='failed'`（持久化），不扣账本，返回 502 `PAYMENT_REFUND_FAILED`，可重试
- Provider 退款成功：`appendEntry type='revoke'` 回收额度，订单 `status='refunded'`, `refund_status='success'`

**退款账本语义**：
- `refund` 类型（原有）：撤销 capture，consumed→available（任务级撤销）
- `revoke` 类型（R09 新增）：订单退款回收，从 available 扣除（不碰 consumed）

**订单退款状态机**：
```
settled_real ──退款成功──→ refunded (refund_status=success)
settled_real ──退款失败──→ settled_real (refund_status=failed, 可重试)
refunded ──再次退款──→ 409 ORDER_ALREADY_REFUNDED
```

**版本**：
- `src/server.mjs`：0.19.0 → 0.20.0，module R08 → R09
- `package.json`：0.19.0 → 0.20.0，test 命令增加 test/r09.js

**测试覆盖**（11 个新增用例，test/r09.js）：
- revoke 账本类型：从 available 回收，不影响 consumed；超量回收抛 `REVOKE_INSUFFICIENT`
- `refundableCreditsForOrder`：按 source_order_id 计算可用批次量
- 退款成功：settled_real → refunded，回收可用额度，金额按比例
- 重复退款：ORDER_ALREADY_REFUNDED
- 演示订单不能退：ORDER_NOT_REAL_MONEY
- 未结算订单不能退：ORDER_NOT_SETTLED
- 退款失败可重试：provider 抛错后记录 failed，重试成功

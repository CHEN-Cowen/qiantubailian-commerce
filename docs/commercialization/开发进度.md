## 3. R08 范围与验收

### 范围

**后端新增文件**：
- `src/providers/wechat.mjs`：微信 Native 支付 Provider（APIv3 签名/验签/AES-256-GCM 解密/下单/查单/关单/退款）
- `src/providers/payment.mjs`：支付 Provider 工厂（`QTB_PAYMENT_PROVIDER=mock|wechat_native`）

**后端修改**：
- `src/m12.mjs::evaluatePaymentCapability`：重写能力闸口，支持 supports_native_qr / supports_query / supports_close 等字段
- `src/api.mjs`：
  - 路由分发增加 `/api/billing/orders/:id/pay`、`/api/billing/orders/:id/query`、`/api/billing/orders/:id/close`、`/api/billing/wechat/notify`
  - `createBillingOrderRoute`：区分 mock / 真实 / 免单三路，真实支付调 `provider.createNativeOrder()` 返回 code_url
  - `settleBillingOrderRoute`：真实支付订单只能回调结算，手动 settle 拦截
  - `queryBillingOrderRoute`：查单自动同步本地状态（provider 返回 SUCCESS 自动 settled_real）
  - `closeBillingOrderRoute`：关单并同步 provider 状态
  - `wechatNotifyRoute`：公开入口，不走认证；签名验证 → 解密 → 根据 out_trade_no 找订单 → 幂等结算
- `src/server.mjs`：版本 0.18.0 → 0.19.0，SERVICE.module R07 → R08
- `package.json`：版本 0.18.0 → 0.19.0，test 命令增加 test/r08.js

**订单状态机**：
```
pending_demo_settlement ──手动 settle──→ settled_demo
plan_first_trial ──自动发放──→ settled_real (price_cents=0)
pending_wechat_checkout ──回调 SUCCESS──→ settled_real (发放额度)
pending_wechat_checkout ──查单 SUCCESS──→ settled_real (发放额度)
pending_wechat_checkout ──手动关单────→ wechat_closed
pending_wechat_checkout ──回调 CLOSED──→ wechat_closed
settled_real ──R09 退款──→ refunded
```

**测试覆盖**（19 个新增用例）：
- evaluatePaymentCapability 三种场景（mock / real_money / mixed）
- Provider 工厂缺配置即抛（不回落到 mock）
- 免单套餐直接发放
- mock 真实支付下单 → pending_wechat_checkout + code_url
- 手动 settle 真实支付订单被拦截
- 关单 / 查单同步 / 回调结算 / 幂等回调 / 找不到订单返回 SUCCESS
- 回调 CLOSED 状态跟随订单
- out_trade_no 格式校验
- 退款路由 REFUND_UNIMPLEMENTED（R09 实现）

## 3. 执行纪律

1. 一次只做一个模块，模块内先实现最小完整变化，再跑检查、修缺陷、复测。
2. 每个模块至少一个独立提交，提交信息 `feat(Rxx): 中文描述`；修复追加提交，不压总提交。
3. 推送同一开发分支并核对远端 SHA；推送被阻断时如实报告，不伪造成功。
4. 高风险行为（身份、金额、额度、生成状态、恢复、退款）必须有能捕获真实问题的自动化检查。
5. UI 变化必须真实浏览器操作与截图验证，不以 HTML 字符串存在代替。
6. 真实模型、真实支付、真实退款一律以外部验收单列，不用模拟验收冒充。

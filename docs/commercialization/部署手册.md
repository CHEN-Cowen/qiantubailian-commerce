# 千图百炼 · 部署手册

适用：0.23.0 / R12 与 2026-10-27 修复后的工作区。

## 环境与启动

Node.js `>=22.22.2 <23`，Windows/macOS/Linux。运行依赖 `sharp`、`qrcode`，使用锁文件安装：

```bash
git clone --branch feat/commerce-commercialization https://github.com/CHEN-Cowen/qiantubailian-commerce.git
cd qiantubailian-commerce
npm ci
npm start
```

根目录 `.env` 由启动脚本读取。监听端口变量是 `PORT`；数据目录变量是 `QTB_DATA_DIR`。PowerShell 示例：

```powershell
$env:PORT='3000'
$env:QTB_DATA_DIR='E:\qtb-data'
$env:QTB_DEMO_MODE='0'
$env:QTB_INITIAL_CREDITS='0'
npm start
```

生产需设置 `NODE_ENV=production`、`QTB_DEMO_MODE=0`，使用同机 HTTPS 反向代理转发至 loopback。默认 Secure Cookie 需要 HTTPS；服务本身只监听本机，不能把 HTTP 开发配置直接当成公网部署。

## 身份与权限

用户从页面注册/登录，服务端 Cookie 保存会话；写请求需要会话返回的 `csrf_token`，放入 `x-csrf-token`。工作区按会话确定，不能用 `x-tenant-id` 或 `x-actor-id` 冒充真实账户。

非生产默认演示身份只用于本机开发。生产拒绝演示身份；邮件找回服务未配置时明确不可用。

## 外部配置

完整变量见仓库 `.env.example`。密钥仅放在部署环境或被忽略的 `.env` 中。

| 配置 | 含义 |
| --- | --- |
| `QTB_PROVIDER=mock` | 默认模拟图像，不调用付费模型 |
| `QTB_PROVIDER=seedream` | 真实图像适配器，需 `PARATERA_API_KEY` 或 `PILOTDECK_SEEDREAM_API_KEY` |
| `QTB_SEEDREAM_POST_COMPOSITE=1` | 显式启用本地主体合成，效果仍需实样验收 |
| `QTB_OCR_ENDPOINT`、`QTB_OCR_API_KEY` | OCR HTTP 服务；无配置就不提取，不伪造结果 |
| `QTB_PAYMENT_PROVIDER=none` | 默认关闭支付 |
| `QTB_PAYMENT_PROVIDER=mock` | 模拟支付演练，不能算真实收入 |
| `QTB_ENABLE_REAL_PAYMENTS=1` | 完成商户和真实交易验收后才启用 |
| `QTB_WX_MCHID`、`QTB_WX_APPID` | 直连商户及绑定的应用 |
| `QTB_WX_APIV3_KEY` | 原始 32 字节 APIv3 密钥 |
| `QTB_WX_PRIVATE_KEY`、`QTB_WX_SERIAL_NO` | 商户私钥 PEM、商户 API 证书序列号 |
| `QTB_WX_PLATFORM_CERT`、`QTB_WX_PLATFORM_SERIAL` | 平台证书/公钥 PEM，以及序列号/公钥 ID |
| `QTB_WX_NOTIFY_URL` | 公网 HTTPS 回调：`/api/billing/wechat/notify` |

用户当前没有商户资质，保持 `QTB_PAYMENT_PROVIDER=none` 和 `QTB_ENABLE_REAL_PAYMENTS=0`。个人收款码不代替 API。默认不收真实资金；支付和模型没有配置时并非所有功能都可用。

## 微信状态与恢复

订单先落库，再调用微信；支付结果以验签通知或验签查单为准，核对订单、金额、币种、商户和 AppID。通知入口不要求用户登录，但必须验签和解密，重复通知不重复发额度。

退款受理为 PROCESSING 时，对应未使用额度冻结；只有 SUCCESS 才记退款完成并回收。网络异常保留冻结和原退款号。ABNORMAL 要在商户平台处理，仍保留冻结。每 30 秒补查待支付订单和处理中退款；页面也可刷新结果。没有真实商户验收前不能宣称已完成真实收款和退款。

官方协议参考：[Native 下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)、[退款通知与异常状态](https://pay.wechatpay.cn/doc/v3/merchant/4012268885)。

## 单实例与备份

当前为**单进程单实例**，JSON 数据与 blob 文件通过进程内写队列维护。不能多实例共享同一目录，否则有覆盖和重复任务风险。`QTB_DATA_DIR` 需使用持久卷，限制文件系统访问权限，监测剩余空间。

租户业务备份接口 `/api/backups` 需要 `backup:manage` 权限、登录 Cookie，创建和恢复还需 CSRF。恢复会替换目标租户业务数据，先保存现状和核对在途任务。租户快照不等于账户、会话及整站备份；整站灾备应在停止服务后保护完整数据目录，并演练恢复。

## 验证与观测

```bash
npm test
npm run check
npm run smoke
npm run healthcheck -- http://127.0.0.1:3000
```

`/healthz` 仅存活和版本；`/readyz` 检查静态资源。`/api/metrics` 需要 `metrics:read` 权限和真实会话。采用率来自反馈，导出率独立；每张消耗额度独立于货币成本，未核验货币成本返回空。

自动测试、浏览器流程、真实外部模型与真实商户交易是不同验证层级。无密钥演示用于验证内部流程；真实模型/OCR/支付需要授权样本和交易验证，当前没有完成。

## CI / CD

### CI（`.github/workflows/ci.yml`）

push 与 pull request 都会在 GitHub 的 `ubuntu-latest`、Node `22.22.2` 上执行：

```bash
npm ci --no-audit --no-fund
npm run check
npm test
npm run smoke
```

任一步失败即红叉，作为推送前的远端保护；同分支的旧运行会被取消。浏览器验收脚本（`scripts/verify-rebuild-ui.mjs`）依赖本机 Chrome，未放进 CI，仍需本地执行。

### CD（`.github/workflows/deploy.yml`）

只在 Actions 页面手动触发，**不会随 push 自动上线**：

> 注意：GitHub 只允许从**默认分支**（本仓库为 `master`）手动触发 `workflow_dispatch`。该工作流目前在开发分支 `product-rebuild-20261107` 上，合并（或单独 cherry-pick `.github/workflows/deploy.yml`）到 `master` 后，Actions 页面才会出现 Deploy 入口。CI 不受此限制，任意分支 push/PR 都会执行。

- 必须选择 `ref`（分支/标签/提交），并输入 `confirm=deploy` 才会执行；
- 使用 `environment: production`，可在仓库 Settings 中配置必需审批人；
- 先在 runner 上跑 `check`、`test`、`smoke`，再用 `git archive` 打包（只含版本库文件，不带 `node_modules`、`runtime`、`.env`）；
- 通过 SSH 上传到目标机，在部署目录解包、`npm ci --omit=dev`、重启 systemd 服务，最后轮询 `/readyz` 直到通过。

需要在仓库 `Settings → Secrets and variables → Actions` 配置：

| Secret | 必填 | 含义 |
| --- | --- | --- |
| `DEPLOY_HOST` | 是 | 目标机地址或域名 |
| `DEPLOY_USER` | 是 | SSH 用户 |
| `DEPLOY_SSH_KEY` | 是 | 该用户的私钥（对应公钥已加入远端 `authorized_keys`） |
| `DEPLOY_PATH` | 是 | 部署目录（`git` 仓库/代码所在目录，`.env` 与 `QTB_DATA_DIR` 不放这里也能保留） |
| `DEPLOY_SERVICE` | 是 | systemd 服务名，例如 `qiantubailian` |
| `DEPLOY_PORT` | 否 | SSH 端口，默认 `22` |
| `DEPLOY_HEALTH_URL` | 否 | 部署机上的健康检查地址，默认 `http://127.0.0.1:3000/readyz` |

目标机前提：

- Node `22.22.2` 与 `npm` 可用，能访问 npm registry（或已配置镜像）；
- 服务由 systemd 托管，且 `DEPLOY_USER` 可执行 `sudo systemctl restart <DEPLOY_SERVICE>`（建议只对该单元配置 NOPASSWD）；
- `.env`、`runtime/`（或 `QTB_DATA_DIR`）不在发布包内，部署不会覆盖密钥与业务数据。

它**不做**的事：不备份数据、不执行数据迁移、不改 `.env`、不合并分支、不切流量。发布前仍按上文完成备份与在途任务核对；部署后若 `/readyz` 失败，先在目标机查看服务日志并回滚到上一提交。

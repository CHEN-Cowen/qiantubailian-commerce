# R03 验收记录：成品额度、预算与账本

- 日期：2026-10-27
- 分支：`feat/commerce-commercialization`
- 版本：`0.14.0`（`SERVICE.module = R03`）
- 结论：代码自检通过；真实收款与退款仍需外部资质（见外部依赖清单），本模块不宣称已可收费上线。

## 1. 范围与实现

| 要求 | 实现 |
| --- | --- |
| 区分供应商成本 / 用户额度 / 人民币支付 | 供应商成本沿用 R02 `attempt.cost`、`run.supplier_cost` 单独记账；用户额度走 `credit_entries`；人民币订单留给 R08/R09，未混写 |
| 体验额度 | 注册时发放 3 张、到账起 90 天、仅限 1 个商品；同租户只发一次（`grant:experience:<tenant>` 幂等） |
| 月度包 / 一次性包 | `src/plans.mjs` 定义 ¥19/10 张（90 天）、¥69/40 张（30 天）、¥199/150 张（30 天）；单次购买、不自动续费、不结转 |
| 预留 / 结算 / 释放 | `reserve` / `capture` / `release` 账本条目；同任务 `job_id` 维度记录 `credit_reservations` |
| 退回 / 到期 / 退款冻结 | `refund` 条目只能退已结算部分且幂等；`expire` 只回收批次可用部分，已预留转 `expired_pending`，释放后再次回收 |
| 幂等与可追溯 | 所有账本条目带唯一操作键；批次记录 `order_id`、`version_snapshot`；余额不能为负 |
| 优先消耗将到期额度 | 批次 FEFO：按 `expires_at` 升序分配，无到期批次排最后 |
| 余额不足不调用模型 | 预留与余额判定在同一 `store.mutate` 内；不足直接 402，任务不入队、无生成记录 |
| 重启一致 | 批次与预留随 `store` 持久化；读路径先 `sweepExpiredLots` 再计算余额 |
| 同版本重复下载不扣费 | 导出/下载只读版本文件，不产生账本条目 |

### 关键文件

- `src/credits.mjs`：批次、FEFO、预留分配、到期回收、退款、旧数据迁移
- `src/plans.mjs`：套餐目录、购买快照、订单发放（幂等）
- `src/api.mjs`：注册发放体验额度、`getCredits` 到期扫描
- `src/store.mjs`：新增 `credit_lots`、`credit_reservations` 表（旧数据按空表迁移）
- `src/jobs.mjs`：预留带 `project_id`，体验额度绑定商品

## 2. 产品规则落地

1. 生成开始前展示最高消耗：沿用 `quote.max_credits`；预留额不足直接拒绝，不静默降级。
2. 系统失败释放：供应商技术失败 `release` 回原批次；未知结果保持冻结直到核对（R02）。
3. 后台记录全部供应商成本：`attempt.cost` 与 `run.supplier_cost` 不被用户额度结算覆盖。
4. 体验额度不是现金：`currency` 仍为内部演示额度，`real_money=false`。

### 关键断言

- FEFO：预留 15 张时，最早到期批次先占 10、后到期批次占 5；结算落回同一批次。
- 到期：批次 1 天后到期、已预留 4 张时，首次扫描只回收 6 张；释放后再次扫描回收剩余 4 张，`expired` 合计 10，余额与批次均非负。
- 体验额度：绑定 `proj_1` 后不能用于 `proj_2`（`EXPERIENCE_SCOPE_LIMIT` 或额度不足），且同租户重复发放返回 `applied=false`。
- 退款：同 `refund:<order>` 重放不新增条目；退款超过已结算部分抛 `REFUND_EXHAUSTED`。
- 套餐：体验 3 张/1 商品；¥19/10 张 90 天；¥69/40 张 30 天；¥199/150 张 30 天；全部 `auto_renew=false`、`rollover=false`。
- 持久化：重启后 `available/reserved/consumed` 与批次 ID 一致；旧数据（仅汇总）自动补 `legacy` 批次后可正常释放。
- HTTP：注册返回 `experience_credits=3`，`/api/credits` 只有 1 个 `experience` 批次且未绑定商品；余额 1 时提交套图返回 402，任务列表与生成记录均为空；同 Idempotency-Key 重复提交只预留一次；重复导出/下载前后余额完全一致。

## 4. 设计决定（可调整的产品假设）

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 月度有效期 | 到账起 30 天 | 避免“自然月”歧义，UI 会明写 |
| 一次性尝鲜包 | 到账起 90 天 | 本模块默认值；后续调整只影响新订单 |
| 是否结转 | 不结转 | 与用户指令一致 |
| 是否自动续费 | 不自动续费 | 全部单次购买，追加包走独立订单 |
| 旧订单价格变化 | 沿用购买快照 | `planSnapshot` 写入批次 `version_snapshot` |
| 体验额度范围 | 1 个商品、3 张 | 防止体验额度被当作长期免费额度 |

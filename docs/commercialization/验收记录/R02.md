# R02 验收记录 · 生成状态、数量、超时与供应商成本安全

## 范围

- `src/jobs.mjs`
  - 本地超时不再判定为可重试失败：原调用保留为 `unknown`，继续按 `provider_job_id` 查询，不释放预算、不重提。
  - 未知调用超过对账窗口（默认 `attemptTimeoutMs × 6`）进入 `needs_attention`，预算继续冻结，等待人工收口。
  - 新增 `reconcileRun`：`provider_failed`（确认无产出→释放）、`provider_succeeded_unavailable`（确认已产出但不可取回→按已发生阶段结算）、`cancelled`（复用取消收尾）。
  - 交付 `count` 展开为独立图片项：第 1 张沿用原 `deliverable_id`，其余 `#2…#n`；每张 1 个版本、1 个产物、1 条尝试。
  - 并发上限分三层：单任务 `maxConcurrency`、供应商级 `providerMaxConcurrency`、租户级 `tenantMaxConcurrency`；触达上限留 `rate_limited` 事件并计数。
  - `supplier_cost` 与 `delivery_completeness` 进入任务快照：内部额度结算、供应商成本上报情况、缺项数量分别可见。
- `src/api.mjs`：`POST /api/runs/:id/reconcile`，权限动作 `run:reconcile`（owner/editor 可用）。
- `src/m11.mjs`：角色矩阵新增 `run:reconcile`。
- `src/pricing.mjs`：导出 `EXTRA_COPY_CREDITS`，与报价追加张数价格同源。
- `src/server.mjs`：新增 `providerMaxConcurrency` / `tenantMaxConcurrency` / `unknownReconcileMs` 注入参数。

## 关键断言

| 场景 | 断言 |
| --- | --- |
| 1 封面 + 2 内页 | `deliverables.length === 3`，`inner` 的 `unit_index` 为 [1,2]，ID 唯一，3 个活动版本，全部成功 |
| 交付完整性 | `expected_units = produced_units = 3`，`complete = true` |
| 本地超时 | 每个交付项最多 1 条尝试；存在 `unknown`；预算继续冻结；转为 `needs_attention`；再次等待不增加尝试 |
| 未知→确认失败 | `reconcile(provider_failed)` → `failed` / `provider_failed_confirmed`，冻结额度全部释放，`consumed = 0` |
| 未知→已产出不可取回 | `reconcile(provider_succeeded_unavailable)` → 结算 `attempt.planned_credits`，`consumed > 0`，`deliveries.complete = false`，供应商成本标记为未回传金额 |
| 取消未知调用 | 取消后 `cancelled`，预留归零、消费为 0，后续推进不新增尝试、不复活 |
| 供应商级并发 | `providerMaxConcurrency=1` 时观察到的并行提交 ≤ 1；两个任务最终完成；`rate_limited_count > 0` |
| 供应商成本 | `supplier_cost.internal_credits_charged` 等于内部结算额度；未回传真实金额时 `provider_cost_reported = false` |

## 回归影响

- `test/m05.js` 两处旧预期按新语义更新：
  - 超时用例改为“未知→待核对→人工核对释放”，不再期待 `limit_reached` 与 `PROVIDER_TIMEOUT` 重试。
  - 预算等待用例改为断言 `reserved + consumed === quote.max_credits`（数量展开后首轮可能已结算部分）。

## 遗留

- 供应商真实账单金额需结算单核对（EXT-07）；当前仅记录内部额度与用量。
- `needs_attention` 的人工收口入口已在 API 提供，后台操作台在 R05/R11 接入。
- 真实供应商查单能力取决于所选 Provider；不支持可靠查单时按未知→待核对处理，不伪造失败。

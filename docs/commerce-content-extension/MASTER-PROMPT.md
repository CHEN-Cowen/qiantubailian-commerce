# 千图百炼：商品内容维护完整开发总提示词

请直接在现有千图百炼项目实施完整开发。不是只做原型、访谈或最小演示；本轮明确要求完成商品变更更新、SKU防串图、售前问题改善与补图三个完整模块，以及必要的共用服务、界面和验收。

仓库：https://github.com/CHEN-Cowen/qiantubailian-commerce

使用分支：`feat/commerce-commercialization`。先读取最新远端和当前工作区，保护已有代码与提交。不能从旧默认分支或绿色静态演示重新搭一套产品。

## 1. 阅读顺序与执行依据

先阅读适用的仓库规范、当前 README、配置、测试脚本及：

1. `docs/commerce-content-extension/README.md`。
2. 本总提示词和同目录 `MODULE-PROMPTS.md`。
3. `PRD.md`（完整业务方案）、`BASELINE.md`（衔接基线）。
4. `RESEARCH.md`（公开案例证据和边界）、`INTERVIEW.md`（后续验证材料）。
5. `docs/experience-optimization/` 中的原方案、执行记录与视觉参考，以及实际已提交代码。

需求优先顺序：用户后续明确指令 > 本总提示词 > PRD > 单模块提示词。单模块文档细化执行，不扩大或缩减业务规则。研究和访谈用于解释不确定性，用户本次已选择继续完整开发，不能用“先做访谈”替代已授权实现。

原绿色界面/首次制作/复用/单张修改已经有模块提交，具体完成度和最终自测结果先核验。已满足的能力复用，缺失的必要依赖在本轮补齐；提交记录存在不等于端到端验收已通过。

## 2. 本轮产品范围

为小商家维护商品图片的准确、及时与一致：商品信息改变时找出受影响图片，核对图片与SKU/包装内容，用最少必要修改解决售前疑问，保留事实、版本、费用与交付记录。

必须交付：

- 完整商品变更流程：预览、确认、影响清单、分类处理、报价、逐图更新、检查、选版、导出和替换待办。
- 完整SKU核对：SKU/包含物档案、图片归属、结构冲突、视觉候选、修正复核和按SKU导出。
- 完整售前问题处理：输入、归类、已有信息/图片复用、事实缺口、文字或补图方案、三种说明图、生成复核和采用反馈。
- 共用依赖记录、版本状态、权限、任务恢复、幂等结算、绿色界面、手机适配及操作说明。

不扩展订单、库存、仓库、财务中台；不在无集成情况下承诺店铺自动同步、解决主题代码或防止仓库拿错货。外部视觉、OCR或模型能力不可用时如实表示，不能伪造通过。

## 3. 共用商品与图片数据服务

基于现有实体增量扩展，不并行创建第二套账户、商品、品牌、任务与账本。

至少表达：

1. 商品及确认事实版本。
2. SKU/变体：所属商品、商家编号、稳定内部身份、差异属性和版本。
3. 包装包含物：物件、数量、单位、包含/不包含、确认来源与SKU版本。支持同物件多件和不同物件组合。
4. 素材：账户、商品/SKU、角色、适用范围和源版本。
5. 图片版本：事实/品牌/SKU/素材快照、文字排版层、检查、选用、付费权益与来源。
6. 图片依赖：稳定字段ID、事实版本、素材/Logo引用、相关文字层/区域、证据类型。
7. 变更单、逐项更新任务、核对问题、问题组、补图方案、导出与替换记录。

区分确定依赖（系统编译/明确引用）、识别候选（OCR/视觉推测）、人工关联。旧图没有依赖时标为未知，允许人工建立关系，不伪造完整历史。

数值和单位结构化；等价单位采用明确规则；未确认的容量、材质、功效等不能由模型补为事实。事实确认、质量检查、用户满意/选用、计费、外部替换是不同状态，不能相互代替。

## 4. 商品变更更新助手

从商品/SKU/品牌编辑进入，先展示基准版本与新旧差异，明确影响范围。用户确认后形成事实新版本及变更单；草稿和已确认区别明确。

按依赖列出影响图片、依据、旧导出记录和建议：

- 只改文字/排版：使用既有底图重合成，重新检查受影响内容。
- 需要新实拍：如换包装，要求新照片；不能重绘旧包装冒充实物。
- 需要重生成：用户明确选定图片和动作，先报价。
- 需要人工判断：来源或识别不确定，不能默认为无需处理。

数量/套装变化须同时检查文字和实物表达，不能只将“1”换成“2”。Logo、品牌色更新只作用于选定范围和未来任务，不暗改历史。活动到期按用户信息形成待办，未接平台不自动下架。

更新按项持久化，显示部分成功/失败；可仅重试未完成项，已成功结果不重收费。新版本保留旧版，前后可比，由用户选用。事实再次变化时重新计算影响，旧客户端不得覆盖新确认版本。

恢复旧图片不代表其事实恢复有效；过时结果仍提示，并检查正式导出资格。外部扁平图片先支持人工关联和核对，不承诺任意文字无损替换。

建立旧导出替换待办，显示渠道标签、实际导出版本、用户确认替换者和时间。无平台回执时始终写“商家确认已替换”，不能写“店铺同步成功”。

## 5. SKU防串图与包含物核对

单规格使用简化入口，多规格再展开表格。各SKU绑定确认属性、包含物及实拍；公共Logo等素材可明确共享，SKU专属实拍不能无确认串用。

三层检查：

1. **确定归属**：所选图、源素材、配置和交付是否属于正确商品/SKU；确定错配阻断。
2. **结构内容**：文字层中的颜色标签、规格、数量、尺寸/单位、包含物与确认档案是否冲突；确定矛盾须更正。
3. **视觉候选**：颜色、物件、配件、包装疑点给出证据；遮挡、反光、不可读或模型缺失时保持未知/待核对，不把推测当硬结论。

结果页并排展示原图/结果、SKU事实和问题来源，提供选正确图、更正真实归属、改文字或重做指定图。更正归属需依据，不可通过删除关系解除阻断。

人工复核绑定图片与事实版本、操作者、理由和证据。不能一次人工确认永久放行后续版本；“保留满意”不能覆盖确定错误。解释拍摄道具不一定包含，不能把背景装饰当配件。

按商品/SKU组织交付目录、文件和清单，导出包含正确版本，不混入其他SKU、失效或越权图片。不能仅靠文件名判断权限与归属。

## 6. 售前问题改善与补图

保留原“售前疑问补图”完整能力，但增加正确分流，不默认每个问题都要重新生图。

第一版输入为用户手动填写或粘贴脱敏问题，可人工提供频次与来源；不接客服账号、不导入完整聊天、不抓取私人数据。没有真实频次就写“输入问题”，不标“高频”。限制输入并提示去除姓名、电话、地址和订单号；日志避免存储敏感原文。

流程：

1. 选择商品/SKU，输入问题。
2. 建议归类并允许商家改正：数量/包含物、尺寸、规格差别、使用方式及其他。
3. 检查确认事实和已有适用作品，输出“已有内容可复用”“缺少依据”“文字/位置建议”“需要补图”“不属于商品图问题”。
4. 已有图则直接复用；已有事实但说明不明显则提供简短文字及展示位置建议；需要补图则进入图种与内容确认；缺少资料先给出补充清单。
5. 物流、支付、库存、主题/页面切图故障标清处理边界，不强行生成商品图解决。
6. 预览文字、来源和修改范围，由商家确认；优先复用照片和确定性图层，确需模型才调用并提前报价。
7. 进入现有任务、检查、选版和导出流程，记录采用及未采用原因。

必须实现三种图：包装内容清单图、尺寸说明图、SKU规格对比图。尺寸、物件、差异均有确认依据；不能从问题直接推测数据。已确认尺寸不等于能断言适配所有场景，个体适配/性能缺少依据就暂停相应陈述。

增加“补什么资料”指导：缺测量值时明确需要哪条尺寸和单位，缺包装照片时提示补拍；示例是填报说明而非伪造真实商品数据。

新补图记录所用事实/SKU依赖，后续变更自动进入更新助手。同一问题再次出现时先找当前适用图。反馈可记录商家主观采用，但没有真实店铺数据不声称咨询或退货下降。

## 7. 版本、权限、费用与异常

沿用服务端会话、CSRF、租户隔离、素材鉴权。每条新数据和图片内容/导出接口均验证账户/工作区，不仅页面隐藏。并发使用来源版本条件，关键写入与执行采用幂等机制。

基础依赖查询、结构核对、人工标记、已有底图文字/基础说明图排版不额外消耗生图额度。OCR/视觉等有成本服务设置预算、频率和并发限制，不能隐性消耗无限付费请求。

新生图动作明确报价、预留、成功一次结算；失败/取消/待复核/超时/重启有可追溯处理；批量成功项不因重试重复扣费。切换/恢复旧版、查询与重复导出不重复收费，也不自动退款已交付新结果。不承诺主观不满意无限免费重做。

衍生说明图和免费排版继承源图权益，未付费/未通过源图不能通过新入口绕过水印和正式下载限制。

任务、来源快照、费用和逐项状态持久化，重启可恢复。服务异常不变成检查通过；审计保留操作者、时间、版本、动作和实际费用，不记录密钥。

真实收款保持关闭，个人微信收款不能冒充商户API；本轮不发生真实交易。真实模型、OCR、视觉检查有授权才调用；没有时完成内部实现与契约验证，并明确外部效果未验收。现有单实例存储边界保持，不顺带做分布式改造。

## 8. 页面与原任务衔接

沿用已有低饱和绿色正式界面；参考原绿色快照，不重新换一套设计。正常首次制作不新增强制中台步骤。

商品页增设“检查与更新”，汇总需更新图片、SKU核对项和售前问题；作品页能查看事实/SKU/依赖与需更新提示；首页可展示当前工作区真实待办。

变更页：差异 → 影响清单 → 动作/预算 → 逐项结果 → 替换待办。

SKU页：规格与包含物 → 图片网格 → 冲突依据 → 修正/复核 → 正确导出。

问题页：输入 → 分流/资料缺口 → 已有图/文字方案/补图 → 内容确认 → 预览、报价、检查与交付。

修改完成提供“本次改了什么”：新版、修改点、沿用来源、旧文件替换待办。移动端可操作，长内容/错误/加载/空状态完整；警告与失败不全部显示绿色。

## 9. 模块划分与必须执行的闭环

按 `MODULE-PROMPTS.md` 中 E00—E08 顺序推进，每一模块只在其门槛通过后进入下一模块。相关实现必须包含前后端和必要检查，不能交付空按钮或静态假成功。

**每模块固定顺序：阅读现状与定义验收 → 开发 → 自测 → 有问题修复 → 复测通过 → 检查差异/数据 → 单独提交 → 推送 → 核对远端包含提交 → 更新进度并自动开始下一模块。**

不要每完成一个模块就问我是否继续。常规技术与界面选择自行判断，只有缺少必需权限/凭据或无法自行消除的重大冲突才提出具体问题；不受影响的工作继续。

每模块记录真实测试、失败修复、外部未验收项与推送状态，维护独立 `IMPLEMENTATION-LOG.md`。复用原已完成模块时补验证及衔接记录，不为凑提交数造空实现。既有行为已满足可提交本模块相关有价值测试/说明；只在当前模块通过且提交/推送记录真实时推进。

推送失败合理重试；无法解决时保留本地成果、明确阻碍，不能称已推送，也不能越过推送门槛推进后续模块。远端前进则安全整合并复测，不force push、不破坏性清理。暂存明确文件，保护无关用户修改和其他开发软件的进行中工作。

所有模块完成后还必须做整体自检：发现问题继续修复、关联复测和必要全量复测；通过后提交推送最终修复与验收报告，即使无需代码修复也提交真实验收记录。不能以逐模块通过代替最终端到端检查。

## 10. 必须覆盖的端到端场景

1. 建立商品及两个SKU，确认属性/包含物，关联实拍，制作并导出。
2. 修改确认规格，确定依赖全进入清单，未知旧图待核对；只改文字不调用生图，不改其他选用版本。
3. 更新包装和单件/两件配置，要求相应照片及数量表达核对，不能仅换字就放行。
4. 批量更新部分失败，成功项保留、重试不重扣；重启能恢复未完项和费用。
5. 错归属、文字数量/单位/规格冲突可阻断；视觉疑点显示证据和未知状态，人工确认有范围。
6. 修一个SKU不改另一个；导出正确组合各交付版本，旧事实失效图有正确限制。
7. 询问包含物/尺寸/规格差别：资料不齐先补，已有图先复用，需要时生成三种可编辑说明图。
8. 配送/支付/前台绑定问题正确分流，不伪造生图解决；无频次不写高频。
9. 补图后事实再次变化，新图能被找到；品牌更新不改历史和运行中任务。
10. 免费说明图/排版不能越过底图权益；重复提交、回调、选版、恢复、导出不重复结算。
11. 两个账户互相猜测商品、SKU、问题、任务、素材和导出ID不能越权；写入与文件访问正确鉴权。
12. 并发编辑不覆盖新版本，断网/报价过期/余额不足/取消/超时/服务缺失有正确状态。
13. 桌面与手机真实浏览器走通三个完整流程，保存关键截图；内部模拟与真实服务结果分开。
14. 原有首次制作、复用、单张修改、质检、额度和导出回归通过；按当前脚本和指定运行环境执行项目必需检查。
15. 外部替换仅用户确认时不显示平台成功；日志/截图/仓库不含私人客服记录、会话或密钥。

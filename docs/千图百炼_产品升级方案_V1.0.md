# 千图百炼：电商视觉增长工作台

**版本**：V0.1 产品方案（仅规划，不改代码）  
**日期**：2026-10-24  
**目标用户**：中小电商商家、品牌电商团队、代运营与设计服务商。

---

## 1. 一句话定位

> **千图百炼让商家从一个商品素材包出发，生成可上架、可投放、可迭代优化的商品图、短视频和多平台详情页。**

不把产品定位成“提示词生图工具”，而是定位成“电商商品视觉生产与校验工作台”。商家不需要学习提示词，也不需要在多个工具间复制、裁剪、返工。

### 核心价值主张

- **一次上传，产出一套货**：商品主图、卖点图、场景图、短视频、详情页模块同步生成。
- **先约束，再生成**：先读取商品、品牌和平台规则，降低“图好看但商品不对、平台不能用”的风险。
- **把返工变成自动循环**：保留现有“生成 → 评审 → 修订 → 再生成”的核心能力，但把评审标准换成电商可用性。
- **一次配置，批量复用**：品牌资产、视觉风格、商品类目模板和平台尺寸沉淀为可复用资产。

### 明确不做

- 不做通用的“无限画布式”AI 设计平台。
- 首期不承诺直接替代专业摄影、模特实拍或人工合规审核。
- 不以开放式提示词编辑器作为主入口。专业模式可以保留，但不能成为主流程。

---

## 2. 要解决的关键问题

| 商家现在的阻力 | 千图百炼的解决方式 |
|---|---|
| 反复修改提示词，仍难稳定复现 | 用“商品事实 + 模板 + 品牌规则”代替空白提示词；每轮自动锁定已正确内容，只改失败项。 |
| 商品在 AI 图里变形、颜色错、卖点丢失 | 建立商品真实性检查和硬约束：轮廓、文字、材质、颜色、配件、数量。 |
| 一张图不能覆盖多渠道 | 按淘宝/天猫、抖音、小红书、京东、拼多多、Amazon、Shopify 等预置尺寸和内容结构。 |
| 商品图、视频、详情页分散生产 | 围绕 SKU 创建“商品项目”，统一管理素材、版本、输出和审核记录。 |
| 不知道什么视觉能转化 | 后续引入素材表现反馈，形成“生成—投放—回流—再生成”的闭环。 |

## 3. 产品框架：从“创作工作台”升级为“商品项目”

### 一级导航

1. **商品项目**：按 SKU/活动管理全部视觉资产，是默认首页。
2. **快速生成**：从单张商品图快速产出一个任务。
3. **批量生产**：CSV/Excel 或商品链接导入，批量生成固定模板。
4. **品牌资产**：品牌色、字体、Logo、禁用词、模特/场景风格、历史优秀素材。
5. **模板中心**：按行业、平台、目标选择模板。
6. **素材库与版本**：可检索、可复用、可对比、可导出。
7. **数据与优化**：第二阶段上线，接入素材表现或人工标注结果。

### 一个“商品项目”的固定结构

- **商品事实卡**：名称、类目、价格带、规格、材质、核心卖点、不可变元素、禁用表达。
- **素材包**：白底图、细节图、包装图、Logo、已有视频、参考图。
- **品牌套件**：色彩、字体、调性、镜头语言、文案语气。
- **平台包**：目标平台、尺寸、主图规则、文案长度、是否允许人物/价格/促销信息。
- **内容任务**：商品图、视频、详情页三类输出。
- **质检与版本**：每轮问题、修订原因、通过状态和可发布文件。

## 4. 核心用户流程

### A. 新品上架：推荐作为首发主流程

1. 点击“创建商品项目”，上传 1–6 张商品实拍图，或粘贴商品链接。
2. 系统识别品类、主体、颜色、材质、包装与可见卖点；用户只需确认商品事实卡。
3. 选择目标：“上新详情页”“投放素材”“短视频种草”或“整套上新”。
4. 选择平台和品牌风格，系统展示推荐内容清单与额度预估。
5. 一键生成“首版商品包”：主图、卖点图、场景图、视频分镜和详情页草稿。
6. 电商质检自动逐项给出：商品一致性、平台规格、文字、构图、风险项与可用等级。
7. 用户对某项点选“保持商品不变，改背景/构图/模特/文案”，自动发起局部修订。
8. 通过后导出平台目录，或进入“批量生成同款 SKU”。

### B. 广告测试：以“假设”而非“重写提示词”驱动

输入：商品项目 + 广告目标（点击、收藏、转化）+ 人群/场景。  
输出：3–5 套可区分的视觉方向，例如“功能痛点”“氛围感”“对比展示”“达人种草”。

用户可将其中某一版设为“基准版”。后续迭代只允许替换一个变量，便于归因：首屏钩子、背景、卖点、模特、CTA 或镜头节奏。

### C. 批量铺货：第二优先级流程

导入 SKU 表 → 绑定统一品牌与模板 → 自动补全商品事实 → 先生成低成本预览 → 人工抽检 → 对通过条目批量出高清图/视频 → 按平台导出。

## 5. 把现有核心能力迁移为“电商自优化引擎”

现有能力已经具备：**场景理解 → Prompt 生成 → 图片生成 → 图片评审 → Prompt 修订 → 多轮迭代**，并且记录每轮产物与评分。这是产品的差异化底座，应完整保留。

### 新的生成前结构：CommerceSpec

将当前 SceneSpec 扩展为 `CommerceSpec`：

- `product_truth`：商品外形、颜色、材质、部件、包装、数量、文字/Logo；不可改动。
- `brand_rules`：品牌视觉、调性、禁用内容、版权/合规提示。
- `channel_rules`：平台尺寸、主图规则、文案限制、目标比例。
- `content_goal`：上架、种草、转化、活动、再营销。
- `creative_direction`：场景、镜头、模特、光线、卖点优先级。
- `deliverables`：每种图、视频和详情页模块的数量与格式。

### 新的质量评审：Commerce QA

除美学分数外，必须展示可操作的业务评分：

| 检查项 | 说明 | 是否阻断发布 |
|---|---|---|
| 商品一致性 | 外观、颜色、部件、数量、包装、Logo 与参考素材一致 | 是 |
| 卖点可读性 | 关键卖点是否被视觉表达，文字是否可读 | 视平台规则 |
| 平台适配 | 尺寸、比例、留白、主图限制、导出格式 | 是 |
| 视觉质量 | 清晰度、构图、光影、瑕疵、人物/手部问题 | 否，但影响评分 |
| 品牌一致性 | 色彩、字体、镜头、语气符合品牌资产 | 否 |
| 风险提示 | 夸大功效、可能误导、肖像/IP、错误价格与敏感措辞 | 是或人工复核 |

### 自动修订原则

- **锁定**：已通过的商品外观、平台规格、品牌调性不能被下一轮破坏。
- **最小改动**：优先只修一个高优先级问题，避免“改背景又改坏商品”。
- **透明可控**：给用户显示“本轮保留什么、修改什么、为什么修改”，但不强迫其读 Prompt。
- **停止规则**：质量通过、达到预算/轮数、连续无提升，或用户手动停止。

## 6. 关键界面方案

### 6.1 商品项目首页

卡片字段：商品缩略图、SKU 名、目标平台、项目进度、已通过素材数、待复核风险、最近更新时间。  
顶部优先提供两个按钮：**“新品上架包”**、**“从链接/表格批量导入”**。

### 6.2 生成页：从左中右三栏改为“任务导演台”

- **左栏：商品与目标**。商品事实卡、素材包、目标、平台、模板、品牌套件。
- **中栏：交付物看板**。图/视频/详情页以任务卡方式呈现，先出预览，支持筛选“待处理/生成中/已通过/需复核”。
- **右栏：质量与版本**。不再仅显示技术步骤，显示电商 QA 分数、失败原因、保留项和一键修订选项。
- **底部抽屉：制作过程**。保留当前时间线、Prompt、评分和每轮记录，供高级用户/客服排查使用，不占用主操作区。

### 6.3 单个素材详情

左侧显示版本对比滑杆；右侧显示：

- 通过标签：商品真实、平台可用、品牌一致。
- 风险标签：需确认、不可发布。
- 快捷修订：换场景、换角度、提升质感、改文案、改比例、保持商品不变重生成。
- 专业模式：可查看/编辑 Prompt、评分细则和资产引用关系。

### 6.4 详情页编辑器

第一期做“结构化详情页生成器”，避免直接做复杂自由排版：

`首屏主视觉 → 核心卖点 → 使用场景 → 细节特写 → 规格参数 → 信任/服务 → CTA`

每个模块引用已通过的图、视频或文案；按平台一键替换为推荐尺寸与模块顺序。后续才提供拖拽编辑和在线发布。

### 6.5 已确认的 UI 架构与色彩方向

已确认采用 **A 组合方案**：原型二“快捷创意工厂”作为首页入口，原型一“商品项目工作台”作为核心创作与审核界面，原型三“目录生产控制台”在团队版/企业版阶段上线。

#### 页面优先级

1. **首页：快捷创意工厂**。以“新品上架包、广告素材、商品短视频、批量更新”四个任务入口降低首次使用门槛；呈现继续制作、最近交付、额度和本周产出。
2. **核心页：商品项目工作台**。左侧为商品事实、素材、品牌套件和平台规则；中间为图、视频、详情页等交付物；右侧为 Commerce QA、锁定项和局部修订。现有 Prompt、Agent 时间线和迭代记录下沉至底部抽屉或专业模式。
3. **团队页：目录生产控制台**。面向多 SKU 批次处理，提供状态筛选、统一规则、审核队列、批量导出与后续的店铺同步。

#### 视觉气质

采用明亮、克制、可信赖的电商生产工具风格：真实商品素材优先，避免深色赛博风、重渐变和以模型参数为中心的“AI 玩具”界面。卡片使用白色表面、浅灰页面背景、低对比边框和 8–12px 圆角；用留白、商品缩略图、状态标签和版本对比建立层级。

#### 推荐颜色系统：“天青蓝 + 笔墨紫 + 中性云白”

| 颜色角色 | 色值 | 用途 | 使用规则 |
|---|---|---|---|
| 品牌主色，天青蓝 | `#246BCE` | 主按钮、当前导航、链接、进度、选中态 | 每个页面只保留一个主行动按钮，避免大面积铺色。 |
| 主色浅底 | `#E8F1FF` | 选中菜单、信息提示、空状态插画底 | 只用作局部浅底，不作为正文背景。 |
| 创作辅色，笔墨紫 | `#6D5BD0` | “生成中”、创意任务、模板/灵感标识 | 只表示创作过程，不与通过/失败状态混用。 |
| 通过，松柏绿 | `#15803D` / 浅底 `#DCFCE7` | 商品一致性通过、可发布、审核完成 | 只用于已验证结果。 |
| 待复核，琥珀棕 | `#B45309` / 浅底 `#FEF3C7` | 待人工确认、轻度风险、额度提醒 | 不用于普通按钮。 |
| 阻断，朱砂红 | `#DC2626` / 浅底 `#FEE2E2` | 商品不一致、平台规则失败、不可发布 | 只用于需要停止导出或必须修订的错误。 |
| 页面背景，云白 | `#F8FAFC` | 应用整体背景、表格区域 | 保持商品图的色彩和材质成为焦点。 |
| 卡片背景 | `#FFFFFF` | 项目卡、素材卡、弹窗 | 搭配 `#E2E8F0` 的 1px 以下视觉边框。 |
| 主要文字，墨灰 | `#0F172A` | 标题、商品名、关键数字 | 不使用纯黑，降低长期阅读疲劳。 |
| 次级文字，青灰 | `#64748B` | 辅助信息、时间、参数说明 | 不承担关键状态表达。 |

**颜色比例建议**：中性白/灰约 80%，蓝色约 12%，紫色约 3%，绿/琥珀/红等语义色合计不超过 5%。不要用渐变作为界面基础；如需在营销落地页使用渐变，仅可使用极浅的蓝紫背景，不进入商品项目工作台。

#### 关键状态映射

- “生成中、正在优化、模板推荐”固定使用紫色，不让用户误以为已经通过质检。
- “通过、可导出、可发布”固定使用绿色。
- “待复核、存在轻微风险、额度即将用完”固定使用琥珀色。
- “商品事实不一致、平台规则失败、禁止发布”固定使用红色，并同时给出具体修订动作。
- 所有状态都必须带文字或图标，不可只依赖颜色；通过和阻断状态需要在素材卡和详情侧栏同时显示。

## 7. 模板策略：以“任务模板”替代“风格模板”

模板必须包含交付物、约束与质检规则，而非只有一段风格 Prompt。

首期建议 12 个高频模板：

1. 白底主图（通用/平台规则版）
2. 3 张卖点信息图
3. 3 张氛围场景图
4. 美妆护肤高级感套图
5. 服饰平铺/上身展示
6. 鞋包配饰细节展示
7. 家居日用场景图
8. 食品饮料食欲感图
9. 3 秒商品动效/循环视频
10. 8–12 秒新品发布短视频
11. 小红书种草九宫格
12. 商品详情页 6 模块

模板中心的筛选维度：类目、平台、内容目标、风格、是否需要模特、是否支持批量、预计消耗额度。

## 8. 商业化建议

### 原则

采用 **订阅额度 + 按需加油包 + 团队/批量增值能力**。避免将工具按功能层层锁死，用户可用同一额度在图片、视频、详情页之间灵活消耗；每次生成前明确显示预计消耗。

### 建议定价（人民币，首期可 A/B 测试）

| 方案 | 月价 | 适合对象 | 建议包含 |
|---|---:|---|---|
| 体验版 | ¥0 | 试用商家 | 20 点额度/月，带水印预览，1 个品牌项目，不支持商用导出 |
| 个体商家 | ¥59 | 单店新品上架 | 300 点，高清无水印、商用授权、平台导出、基础模板 |
| 增长店铺 | ¥199 | 高频上新/投放 | 1,200 点，品牌套件、批量任务、视频、详情页、优先队列 |
| 团队版 | ¥599 | 品牌/代运营小团队 | 4,000 点，3–5 席位、审批流、共享资产、批量导出 |
| 企业版 | 定制 | 大目录/服务商 | API、SLA、私有模板、用量结算、专属支持 |

建议初始换算，需结合模型成本校准：标准图 4–8 点，高清图 10–16 点，3 秒视频 25–40 点，8–12 秒视频 80–150 点，详情页 30–60 点。失败于“商品一致性/平台硬规则”的自动重试可赠送一次，提升信任。

### 付费触发点

- 免费试用完成首个“可发布商品包”后，再提示导出与商用授权。
- 视频、批量、品牌资产、团队协作是自然升级点。
- 不采用“生成后强制付费看结果”的黑箱模式；免费用户应先看到带水印或低清预览。
- 提供可叠加的点数包，减少低频商家的订阅阻力。

## 9. 借鉴竞品后应采用与避免的做法

### 应采用

- **按商品项目组织**：Seenable 强调从商品图到完整视觉管线与批量生产，适合本产品的 SKU 项目制。
- **品牌资产自动继承**：SharpShoot 的 Brand DNA 思路值得采用，保证多次生成和多人操作的一致性。
- **按渠道预设交付物**：SocialShot AI 的“自动适配平台招商规格”应成为千图百炼的基础能力。
- **先预览再消费**：Artvizon 和 Fovuno 的低门槛体验有利于降低首次使用门槛。
- **图片/视频共用额度**：Seenable 的共享点数池比按功能割裂的套餐更贴近商家的不确定需求。
- **批量流水线**：CatalogMotion 的“导入目录—批量任务—统一下载”适合后续目录型商品客户。

### 应避免

- 只宣传“好看”，不说明商品一致性和可上架性。
- 让用户从空白 Prompt 开始，或强迫理解模型参数。
- 用过多模型入口分散用户决策。默认应由任务和质量目标选择模型。
- 夸大转化率、平台审核或合规的确定性。应明确“自动预检，不替代平台最终审核”。

### 9.1 已确认的差异化与模型能力路线

**核心差异化不应是“模型更多”，而是“可发布的商品资产更稳定”。** 产品定位应升级为：商品不走样、品牌不跑偏、平台可检查、失败可自动修订的电商视觉生产系统。

优先建设五项能力：

1. **商品真实性引擎**：为每个 SKU 建立 `ProductTruth`，明确轮廓、部件、主色、材质、文字/Logo、包装、数量等不可变事实。遵循“锁商品，生环境”。
2. **可发布性引擎**：将商品一致性、平台规则、品牌规范、内容风险和视觉质量共同决定“可发布 / 待复核 / 不可发布”。
3. **品类化工作流**：先深耕美妆护肤，再扩展家居日用，后续再进入服饰配饰。每类沉淀专属事实字段、模板和质检规则。
4. **品牌视觉配方**：沉淀经验证的场景、镜头、光线、构图、参考图、模型、规格、通过率和成本，而不是只保存 Prompt。
5. **结果回流**：先记录使用/驳回/人工评分，后续在授权后把店铺或广告表现回流到创意推荐。

#### 多模型策略

不让商家选择模型，而是按任务自动路由，并通过统一 Adapter 保障可替换性。P0 保留现有 Seedream，同时新增一个高保真精修候选（优先 GPT Image）进行基准集对比；不建议同时接入大量供应商。

| 场景 | 优先路径 |
|---|---|
| 白底主图、包装文字、Logo、型号 | 实拍商品主体保护 + 抠图/合成 + 背景和阴影生成 + OCR/颜色校验 |
| 场景卖点图、低成本预览、相关套图 | Seedream 的多参考/连续生成能力，先出候选再 QA |
| 高价值主图、复杂局部精修 | GPT Image 的多图、遮罩和多轮编辑能力 |
| 多道具、颜色精控、复杂参考合成 | P1 后按评测结果接入 FLUX 多参考编辑 |
| 商品短视频 | 先以通过的真实商品首帧进入图生视频，低幅度运动优先；不要直接从文本生成商品 |

#### 上线与评测规则

建立包含 100 个已授权 SKU 的商品视觉基准集，覆盖玻璃、金属、软包装、布料、印花、食品、细小文字等失败模式。所有候选模型先离线评测，再以 5% 流量灰度。核心指标是商品真实性通过率、OCR 正确率、主色合格率、平台规则通过率、人工一次通过率、时延、单张合格成本和人工修订分钟数。

不建议早期自训通用模型或为普通店铺训练 LoRA。只有在高价值品牌具备充足且已授权的人工确认素材后，才评估私有训练；此前应把投资放在商品事实、质量闭环和品牌配方上。详细技术路线见《千图百炼_差异化与模型能力路线.md》。

## 10. 迭代路线图

### P0：定位验证与界面重构（2–4 周）

- 用“商品项目、任务模板、平台包、Commerce QA”的语言重构现有 Demo 和演示数据。
- 新增新品上架包的完整点击原型，不接真实模型亦可。
- 将当前工作流详情下沉为高级面板，主页面以交付物状态为中心。
- 访谈 8–12 位商家/代运营，验证：愿意上传什么素材、最常做什么内容、对自动校验最关注什么。

**验收**：用户可在 3 分钟内理解“上传商品 → 选平台/目标 → 得到整套商品包”的流程；不少于 70% 受访者能说清与普通生图工具的差异。

### P1：单 SKU 的图片闭环（4–8 周）

- 上线商品事实卡、模板、平台尺寸输出。
- 将现有 SceneSpec/评审/修订映射为 CommerceSpec/Commerce QA。
- 图片版本对比、一键局部修订、导出压缩包。
- 建立 3–5 个类目的质检规则与真实素材基准集。

**验收**：商品一致性硬规则失败时不可标记为“可发布”；用户无需编辑 Prompt 也能完成一套图片。

### P2：视频与结构化详情页（6–10 周）

- 商品静态图到 3 秒循环视频、8–12 秒新品视频。
- 生成视频脚本/分镜、视频 QA、短视频平台比例导出。
- 详情页 6 模块生成、模块级替换、平台预设导出。

**验收**：一个商品项目内可以交付图、视频、详情页，且每一项均有可追溯的来源和质检状态。

### P3：批量与增长闭环（持续）

- 表格/链接导入、低清预览、抽检、批量高清渲染。
- 团队协作、审批、资产权限、模板共享。
- 接入商家手工标注或广告/店铺数据，推荐下一轮创意方向。

## 11. 成功指标与风险控制

### 北极星指标

**每周完成并导出的“合格商品包”数量。**  
它比生成图片数量更接近商家真实价值。

### 配套指标

- 首次完成商品包的时间（目标：< 10 分钟）。
- 每个合格商品包的人工操作次数与平均迭代轮次。
- 商品一致性硬规则一次通过率。
- 可发布素材导出率、7/30 日复用率、订阅转化率、单个 SKU 的边际成本。

### 主要风险与处理

| 风险 | 处理方式 |
|---|---|
| 商品细节被模型篡改 | 强制商品事实卡确认；高风险类目必须参考图比对；失败自动拦截。 |
| 平台规则经常变化 | 平台规则引擎独立配置、标记版本与生效日期；仅宣称预检。 |
| 视频成本高、等待长 | 先提供分镜和低清预览；高清渲染异步队列；收费前报价。 |
| 用户不信任“自动改提示词” | 显示锁定项、修订目标、前后版本与得分变化；允许回退。 |
| 模板泛化、品牌千篇一律 | 品牌套件与客户私有模板优先于公共风格模板。 |

## 12. 下一步建议：先做三项验证，不进入开发

1. **确定首发人群**：建议优先“月上新 10–100 个 SKU 的中小品牌商家/代运营”，不要同时服务个体卖家、大品牌和摄影师。
2. **确定首发类目**：建议先选美妆护肤、鞋服配饰、家居日用中的一个，再建立商品事实和质检规则基准。
3. **制作 P0 可点击原型并做访谈**：用“新品上架包”完整流程测试定位、模板命名、质量报告和付费接受度；确认后再修改代码。

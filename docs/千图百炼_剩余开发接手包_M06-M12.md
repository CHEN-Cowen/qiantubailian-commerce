## 1. 项目是什么

千图百炼是面向中小电商商家、品牌团队和代运营的**电商商品视觉生产与校验工作台**。目标是从真实商品素材生成可上架、可投放、可迭代优化的商品图、短视频和多平台详情页。

不要把它做成：

- 通用无限画布
- Prompt 工具
- 只追求好看的 AI 生图小工具
- 小说场景图 Agent（仓库 README 里的旧描述已经过时）

核心原则是**锁商品，生环境**：

- 商品主体、包装文字、Logo、型号优先真实素材保护与合成。
- 模型主要生成背景、光影、道具和环境。
- 生成完成和质量通过必须分开。
- 状态必须明确为可发布、待复核或不可发布，并给出原因。

## 3. 技术约束

- Node.js 22.22.2
- 原生 ESM
- 零外部依赖
- 原生 `node:http`
- 原生 `node:test`
- 数据存在 `runtime/`，已被 `.gitignore` 排除
- 可用 `QTB_DATA_DIR` 覆盖数据目录

常用命令：

```bash
npm test
npm run check
npm run smoke
npm start
```

新增前端静态文件时，必须同步修改 `src/server.mjs` 的 `STATIC_FILES` 和相关测试。新增测试文件时，必须同步修改 `package.json` 的 `test` 脚本，否则不会执行。

## 4. 已完成代码不能重写

现有核心文件：

```text
src/server.mjs      HTTP 服务与静态白名单
src/api.mjs         API、租户上下文、SSE
src/store.mjs       JSON/blob 持久化
src/domain.mjs      商品项目、素材、事实与生产闸口
src/catalog.mjs     模板与平台规则基线
src/spec.mjs        品牌套件、冲突、CommerceSpec
src/credits.mjs     只增额度账本
src/pricing.mjs     报价与价格版本
src/provider.mjs    确定性模拟 Provider
src/jobs.mjs        任务状态机、尝试、事件、恢复
frontend/           已有 M02—M05 界面
test/               已有 M01—M05 测试
```

必须复用的契约：

1. `src/domain.mjs` 的 `computeReadiness` 是唯一生产闸口。
2. 商品事实、CommerceSpec、事件、账本都按追加或不可变版本处理，不覆盖旧记录。
3. 跨租户一律 404，不泄漏对象是否存在；未知租户头返回 403。
4. 事件主键是 `event_id`，不是 `id`。
5. SSE 事件名必须是 `event: message`。
6. 终态标记不写 `id:` 行；前端从消息载荷的 `terminal` 字段识别终态。
7. EventSource 不能自定义请求头，SSE 租户必须走 query。
8. `store.persist` 必须处理 Windows 瞬时写入错误并重试。
9. `jobs.stop()` 必须等待在途任务结束。
10. 平台规则覆盖不足只能标 `unknown`，不能声称平台通过。
11. 报价哈希只含清单结构，背景和 Logo 变化不触发重新报价。
12. 当前额度和报价是演示额度，不代表真实货币。

## 5. 剩余模块执行顺序

一次只做一个模块。每个模块都要：开发、自检、修复复测、展示证据、请求提交授权、提交后核对远端、再请求下一模块授权。

### M06 真实生成与商品主体保护

要做：

- 在现有 Provider 契约上接真实 Adapter，先优先 Seedream。
- 实现主体掩码、真实主体合成、参考图职责和生成记录。
- 校验实际能力；不支持主体保护时明确拒绝，不能静默丢弃。
- 保存模型、请求、成本、版本、输出哈希和时延。

不能做：

- 不能把模拟图说成真实模型图。
- 没有密钥时可以先完成模拟与拒绝路径，但必须标“真实模型未验收”。
- 不能绕过 M03 的生产闸口或 M05 的额度结算。

### M07 Commerce QA 与人工复核

要做：

- 文件、尺寸、OCR、商品主体、颜色、视觉、品牌和风险检查。
- 每项结果为 pass、fail、unknown 或 not_applicable。
- 硬失败为 blocked；必要项未知为 needs_review。
- 高美学分不能覆盖硬失败。
- OCR 不可读、检测服务失败必须待复核，不能当成通过。
- 人工确认只允许用于明确可裁决的未知项，并记录人、理由和证据。

不能做：

- 不能用占位检测器直接放行。
- 不能让普通用户把商品事实错误或平台硬失败强制改成通过。

### M08 自动修订、版本与正式导出

要做：

- 自动修订只改可修复问题，优先一次处理一个关键项。
- 保留已通过项，记录保留项、变化项和原因。
- 轮数、预算或连续无改善时停止。
- 支持版本对比、回退和失效复检。
- 导出 ZIP、图片、manifest 和 QA 摘要。
- 完整包与部分包分开；stale 结果不能正式导出。
- M08 结束后先做一次 P1 端到端回归。

### M09 模型精修与质量基准

要做：

- 落地 100 SKU 授权评测集和留出集。
- 评估 GPT Image 等候选精修模型。
- 做冠军—挑战者、最多 5% 灰度和回退配置。
- 报告真实性、未知率、人工接受率和合格成本。

不能做：

- 候选未胜出不能切成默认模型。
- 没有授权素材不能虚报评测完成。

### M10 视频与结构化详情页

要做：

- 先做结构化详情页，再做分镜和首帧图生视频。
- 详情参数必须有来源。
- 视频中间帧异常必须可阻断。
- 图、视频、详情页可联合导出。
- 不支持 HTML 直传的渠道不能承诺直传。

如果实际改动过大，先问用户是否拆成“详情页”和“视频”两个模块。

### M11 批量、团队与品牌配方

要做：

- SKU 导入映射、逐个预览、预算确认和批量导出。
- 目录生产控制台。
- 成员、权限、审批、共享和私有配方。
- 单 SKU 失败不能拖垮整批。
- 审批后的变更必须让旧结果失效。
- 跨品牌、跨租户隔离。
- 批量不能用抽检替代硬检查。

### M12 结果回流、商业化收口与全量验收

要做：

- 采用、驳回、授权效果导入和实验口径。
- 套餐、真实支付、退款，仅在条件具备时做。
- 可观测性、备份恢复、部署准备。
- 全部模块完成后的最终端到端验收。

不能做：

- 真实支付、外部平台数据和品牌训练不能用模拟实现冒充生产完成。
- 私有训练不是默认交付，除非用户另行授权并提供素材。

## 6. 最终验收

全部模块完成后必须跑完整链路，不只汇总测试：

1. 创建项目、上传真实授权素材、确认商品事实。
2. 选择品牌、模板、平台，检查报价和预算。
3. 启动任务，验证排队、生成、SSE 断线续传、QA、修订、人工复核和回退。
4. 注入包装文字错误、主体变形、OCR 不可读、规则过期，确认不会误标可发布。
5. 验证余额不足、并发预留、重复提交、超时、取消后迟到结果、进程恢复和退款释放。
6. 导出完整包和部分包，检查文件、尺寸、命名、manifest、来源和质量快照。
7. 覆盖视频异常帧、详情页来源、批量失败隔离、审批变更失效和反馈口径。
8. 验证跨租户、下载授权、权限和敏感日志。
9. 做性能、备份恢复、模型基准和合格成本检查。
10. 输出最终报告，列明环境、命令、结果、限制、未运行项和是否可发布。

## 7. 必须如实声明的限制

- 当前仓库里的生成结果来自确定性模拟 Provider，不是真实模型商品图。
- 当前额度和报价是内部演示额度，不是真实货币或可计费权益。
- 平台规则基线 `source.verified` 全为 false，未核验官方条款，不能声称已符合某平台要求。
- 没有真实密钥、真实授权素材或真实外部服务时，只能标“未验收/阻断”。

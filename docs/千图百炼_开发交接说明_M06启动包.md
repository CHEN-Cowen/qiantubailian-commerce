## 1. 项目是什么（接手方必读，别跑偏）

**一句话**：面向中小电商商家、品牌团队和代运营的**电商商品视觉生产与校验工作台**。从真实商品素材生成可上架、可投放、可迭代优化的商品图、短视频和多平台详情页。

**不做什么**（极易做偏，重点强调）：

- 不做通用无限画布，不做 Prompt 工具；
- 商家按**商品项目 → 任务模板 → 平台目标**操作，不是按功能菜单操作；
- 不是「AI 画图小工具」，核心承诺是**可发布性**（可上架、可投放），不是图好不好看。

**技术护城河**（决定实现取舍，务必理解）：

1. **ProductTruth 商品事实** —— 商品的真实属性是唯一事实源，生成不能改它；
2. **可发布性 QA** —— 生成完成 ≠ 质量通过，两件事必须分开；
3. **品类工作流 + 品牌视觉配方**；
4. **结果回流**。

**核心原则「锁商品，生环境」**：主图、包装文字、Logo、型号优先用**真实商品主体保护与合成**；生成模型主要处理**背景、光影、道具**。状态必须输出可发布 / 待复核 / 不可发布及原因。

## 3. 强制流程约束（用户铁律，不可省略）

1. **每模块单独授权**开始 → 开发 → 自检 → 展示改动与证据 → 询问是否提交推送 → **用户明确授权后**才 commit + push → 核对远端 SHA → 再单独问是否开始下一模块。
2. **提交授权不自动包含下一模块。** 用户说「提交」只授权提交。
3. 读远端 / pull / merge **不等于**提交授权。任何 pull/merge/rebase 前先检查工作区，禁止覆盖本地修改。
4. 提交前必须复跑测试并展示具体结果；**不得把未通过检查的内容当完成版本提交**。
5. 缺陷修复需复测；修复提交同样需要授权。
6. **模拟验证与真实验证分开报告**。未验收不可宣称完成。
7. 禁止强推、跳过钩子、把凭据写入仓库。
8. 密钥只记录用途、存放位置、环境变量名、权限范围；**明文密钥不进 memory、代码、日志**。

用户原话要点：「每次开发完以后……先需要进行一遍自检」「获得授权后……提交并推送远端」「然后再来询问是否进行下一模块」。

## 5. M03 / M04 / M05 已定契约（M06 必须复用，不得另写一套）

**这些是实际踩坑后定下的，重犯即返工。**

### 5.1 事件与 SSE（M05 踩坑最多）

| 契约 | 原因 |
|---|---|
| 事件主键是 `event_id`，**不是** `id` | 事件对象没有 `id` 字段，写 `data.events[event.id]` 会让所有事件落到同一个 `undefined` 键，每次落盘只留最后一条 |
| SSE 事件名必须统一 `event: message` | EventSource 只把 `message` 映射到 `onmessage`；自定义事件名（如 `run`）会「连上了但收不到事件」 |
| **终态标记不写 `id:` 行** | 按 SSE 规范只有携带 id 的事件才更新客户端 `Last-Event-ID` 游标。写 id 会与最后一条真实事件重号，或让游标变成非法值 |
| 前端从 message 载荷的 `payload.terminal` 识别终态 | **不得**监听不存在的 `terminal` 事件名 |
| SSE 租户走 query（`?tenant_id=`） | EventSource 不能自定义请求头 |
| `run.last_sequence` 单调递增，是续传游标的唯一依据 | 断线续传不丢事件、不重放 |

### 5.2 账本与任务

- 账本**只增**：`reserve` / `capture` / `release` / `refund`，唯一操作键保证幂等，余额不为负。
- 只结算**成功尝试**，余量释放；取消后迟到结果**不复活**、不扣费。
- 预算不足进入 `awaiting_confirmation`；拒绝追加预算按取消处理（无部分释放）。
- 跨租户一律 **404**（不泄漏存在性）；未知租户头 403。

### 5.3 事实与闸口（M03）

- `src/domain.mjs` 的 `computeReadiness(project, assets, truth)` 是**唯一生产闸口**，M06 不得另写一套。
- 事实版本 **append-only** + `base_version` 乐观锁。
- 素材角色：`subject`（主体）与 `packaging`（包装）是**单槽职责**；`style` 图**不能**作为事实来源或不可变区域。
- 风格图不可变区域不成立；`IMMUTABLE_REGION_INVALID` 已有此校验。

### 5.4 快照与规则（M04）

- CommerceSpec **append-only** + 乐观锁；旧快照内容与哈希不变，只判 `stale`。
- 平台规则优先级**编码进冲突数据**（平台 > 事实 > 品牌 > 模板 > 创意），**不允许「忽略平台」选项**。
- 覆盖不足只能是 `unknown`（`platform_coverage`），**永远不能声称平台通过**；`can_claim_platform_compliance` 恒为 false。
- 报价哈希**只含清单结构**（项数/尺寸/比例/格式/文字块），背景与 Logo 变更不触发重新报价。
- 平台规则基线的 `source.verified` **全为 false**，是内部演示基线，**未核验官方条款**——不要在 M06 里声称已符合某平台规则。

### 5.5 持久化与关停

- `store.persist` 对 `EPERM` / `ENOENT` / `EACCES` / `EBUSY` / `EAGAIN` 需**重试**（Windows 瞬时写入冲突）。
- `store` 有 `assertTableKeys` 主键防线，`normalize()` 与 `mutate()` 双路径调用；禁止 `undefined` / `null` / 空串当主键。
- `jobs.stop()` **必须 await 在途 Promise**（`inFlight` 集合），否则测试删目录后 tick 仍在写盘。
- 服务关停顺序：停调度 → 等在途任务 → 排空写队列（`api.drain()`）→ resolve。

## 6. M06 范围定义

### 6.1 计划原文

> **M06 真实生成与商品主体保护** | P1 | Provider Adapter、接现有 Seedream、实际能力校验、主体掩码/合成、参考图职责、生成记录与受控外部调用 | 接口模拟测试与小样真实验证分开；不支持保护时明确拒绝；文件实际格式正确；成本与版本留存

### 6.2 PRD 相关契约（原文摘录）

**5.3 生成与自动修订**

| 编号 | 行为规则 | 验收要点 |
|---|---|---|
| FR-020 | 开始前冻结 CommerceSpec、报价与预算 | 任务可重放其依据 |
| FR-021 | 关键包装使用真实主体合成；环境由模型生成 | 原始主体与掩码版本可追溯 |
| FR-022 | 异步任务显示排队、生成、评审、修订阶段 | 刷新后状态恢复 |
| FR-023 | 建议默认最多 3 轮含首轮，并有总费用上限 | 任一上限触达停止 |
| FR-024 | 自动修订仅针对可修复问题，优先一个关键项 | 记录保留项、变化项、原因 |
| FR-025 | 连续两轮关键问题无改善或主体不可修复则停止 | 显示原因与人工选择 |
| FR-026 | 用户可取消；已运行供应商若不能取消则本地阻止后续阶段 | 迟到结果不得恢复已取消任务 |
| FR-027 | 供应商超时/限流按受控次数重试，仍失败返回可恢复状态 | 幂等，不重复任务或收费 |
| FR-028 | 手工专业 Prompt 修改需另存版本并重新全量 QA | 不绕过事实与硬约束 |

> 相似度不是商品真实的充分证据。主体保护需记录区域与允许的几何/光照变换；掩码外生成、边缘融合及输出压缩后也要检查。未提供足够视角时，不承诺生成正确背面或内部结构。

**第 8 节 Provider Adapter 契约**（Provider 不暴露给默认商家流程）

| 方法 | 必须行为 |
|---|---|
| capabilities | 声明图/视频、参考数量、掩码、尺寸、异步、取消和种子支持 |
| validate | 对不支持的约束明确拒绝，**禁止静默丢弃主体保护** |
| estimate | 返回价格版本、预估成本、误差区间或上限 |
| submit | 带内部任务 ID、请求哈希与供应商幂等键（若支持） |
| poll | 区分排队、运行、成功、失败、未知，**不把未知当失败重复提交** |
| cancel | 返回已取消/不能取消/已完成；系统本地停止仍生效 |
| normalize_result | 保存实际模型、用量、时延、原始请求 ID 与输出哈希 |

标准错误：`INVALID_INPUT`、`UNSUPPORTED_CAPABILITY`、`RATE_LIMITED`、`PROVIDER_TIMEOUT`、`PROVIDER_ERROR`、`CONTENT_REJECTED`、`BUDGET_EXCEEDED`、`CANCELLED`。**错误日志不记录访问密钥或临时签名 URL。**

### 6.3 代码基线的现状（M06 的接缝在哪）

已经就位、**不需要重做**的部分：

- `src/provider.mjs` 已按 PRD 第 8 节实现完整契约（`capabilities` / `validate` / `estimate` / `submit` / `poll` / `cancel` / `normalizeResult`），且 `capabilities()` 已声明 `supports_mask: true`、`max_references: 2`。
- `provider.validate()` 已实现主体保护校验：`requires_subject_protection` 为真但缺 `mask_ref` 时返回 `UNSUPPORTED_CAPABILITY`。
- `src/jobs.mjs` 提交尝试时已构造 `requires_subject_protection: true` 与 `mask_ref: mask:${deliverable_id}`（`src/jobs.mjs:436`）。
- `src/domain.mjs` 已有 `subject` / `packaging` 单槽职责与 `style` 不可作事实来源的校验。
- 任务状态机、事件溯源、额度结算、取消与恢复已闭环（M05）。

M06 **真正要新增**的：

1. **主体保护流水线**：从真实主体素材产出**掩码**（mask）与**合成**结果；记录原始主体与掩码版本；检查掩码外生成、边缘融合、压缩后劣化。
2. **真实 Provider Adapter**（如 Seedream）：实现同一份契约；`validate` 对不支持的约束**明确拒绝**，不静默丢弃主体保护。
3. **实际能力校验**：`capabilities` 与实际请求的比对，能力不足时明确拒绝而不是降级。
4. **生成记录**：实际模型、用量、时延、原始请求 ID、输出哈希、成本与版本留存。
5. **参考图职责**在生成请求中的正确表达（主体 / 包装 / 风格 各自如何参与）。
6. **受控外部调用**：密钥走环境变量，错误日志不落密钥与签名 URL。

### 6.4 建议实施顺序（非强制，按此推进风险最低）

1. 先补**主体保护流水线**（掩码生成 → 合成 → 掩码外/边缘/压缩后检查），用确定性数据，不依赖真实模型。
2. 补**生成记录**结构与成本/版本留存字段。
3. 抽**Provider Adapter 接口层**，让模拟 Provider 与真实 Adapter 可互换——**编排逻辑不动**（M05 的 `provider.mjs` 文件头已写明这个意图）。
4. 实现**真实 Adapter**（需用户授权提供凭据；无凭据则先做能力声明与拒绝路径，用模拟 Provider 推进）。
5. 补 API 与前端：生成记录查看、主体保护结果展示、能力不足时的明确拒绝提示。
6. 测试与走查。

### 6.5 硬性质量红线（违反即不合格）

- 不得**静默丢弃**主体保护：能力不支持时必须明确拒绝（`UNSUPPORTED_CAPABILITY`）。
- 不得把**相似度**当作商品真实的充分证据。
- 未提供足够视角时，**不得承诺**生成正确的背面或内部结构。
- 密钥、临时签名 URL **不得**进入日志、错误消息、代码与仓库。
- **模拟验证与真实验证分开报告**；无真实凭据时必须标注「未做真实验证」，**不得宣称已完成真实生成**。

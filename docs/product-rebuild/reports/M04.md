# M04 报告 · 商品信息确认卡与卖点填写

- 状态：本地完成

## 商品信息（替换技术表格）

- 第 2 步改为「问题卡片」：每个字段用一句业务问题 + 一个具体示例呈现（净含量/保质期/材质/尺码等按商品类型变化）。
- 状态只有三种，含义明确：待填写 / 待核对 / 已核对 · 会作为商品事实进入成图；另有「暂不提供」。
- 关键项必须点「已核对」才能确认版本；改动输入会自动取消核对状态，不会沿用旧确认。
- 「原图可见」不再被当成「已确认」：OCR 候选一律待核对，并单独收在折叠区。
- 包装关键文字可填写，随事实版本以 `critical_text` 提交（服务端原有校验不变）。
- 服务端拦截码翻译成人话（例如「还有 2 项关键信息没核对：净含量、材质」），不再直接显示 `UNCONFIRMED_CRITICAL_FACTS`。
- 商品类型随事实版本提交，前端问题清单与服务端校验、事实来源、权限隔离、账本约束均未被绕过。

## 卖点填写

- 新增独立卖点输入与「生成卖点候选」：一次输入，按句号/分号/换行拆成最多 8 条候选，纯前端确定性拆分，不调用模型。
- 每条候选标注：可以直接使用 / 含未确认信息 / 缺依据的功效表达，并给出原因。
- 功效或绝对化表达（美白、治疗、100%、最好等）标为缺依据，只能「使用改写版本」（仅删除功效词，不新增表达）或复制。
- 含数字的句子必须能在已核对事实中找到对应值，否则提示先去核对。
- 只有用户主动点「作为卖点事实加入」的句子才写入事实版本（key=核心卖点，来源 user_input，已确认人记录为当前账号）。
- 未点加入的候选不会进入商品事实，也不会进入成图文案。

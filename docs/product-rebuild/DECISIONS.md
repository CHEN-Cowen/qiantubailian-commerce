# 实现决策记录

## D01 分支与提交

- 专用分支：`product-rebuild-20261107`，从 `feat/commerce-commercialization` 当前 HEAD 建立。
- 不合并主分支、不强制推送、不改生产配置。
- 每个模块独立提交并推送 origin；远端 SHA 核对后方可记为 pushed。
- 工作区已有的主体保护改动（`.env.example`、`src/providers/index.mjs`、`test/m06.js`）与行尾差异不纳入本次模块提交。

## D02 复用现有架构

- 沿用 Node ESM + 原生前端 ES Modules，不引入框架或新构建链。
- 事实来源、服务端校验、租户权限隔离、额度账本保持现有实现，不以 UI 重构绕过。
- 新交互优先复用现有 API：事实版本、quote、run、SSE/轮询、产物下载。

## D03 商品信息确认

- 前端按商品类别给出“可理解问题 + 示例”，字段来自品类模板。
- 每个字段明确状态：照片可见 / 已确认 / 暂不提供。
- 服务端仍是唯一校验方；用途必填项以服务端规则为准，前端只做提前提示。
- 不把“暂不提供”写成“已确认”，不以默认值伪造事实。

## D04 卖点填写

- 卖点一次输入，客户端确定性拆分为候选句，不调用模型。
- 涉及功效/绝对化/比较性表达时提示补依据或改写；改写不得新增功效。
- 无依据的功效句不进入成图文案；用户可以在事实中补充可核验依据。
- 卖点写入事实版本时使用用户输入来源，不伪装为资料提取。

## D05 方案与背景

- 推荐三个可执行方案，给出确定性推荐理由与“示意预览”（明确标注示意，不冒充生成结果）。
- 背景默认给出可执行建议（按品类/用途），不把“填写背景提示词”设为生成前置。
- 自定义一句话背景为可选；品牌与高级设置渐进展开。

## D06 提交后追踪

- 提交后在当前上下文展示任务状态、每项交付进度、真实费用与下一步。
- 以服务端 run 状态为准；不使用定时器伪造进度，不以 toast 代替结果。
- 超时只显示“状态待确认”，并提供立即刷新，不直接归因网站故障。

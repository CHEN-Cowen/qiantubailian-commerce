# 千图百炼新产品 PRD

版本：V1.0 评审稿｜日期：2026-10-24｜状态：待产品、设计、研发评审｜配套：《千图百炼完整升级方案 V1.0》

## 1. 背景、目标与范围

千图百炼将现有小说场景生图循环升级为电商商品视觉生产与校验工作台。保留自动生成 Prompt、生成、评审、修订及版本记录，增加 ProductTruth 商品事实、主体保护、Commerce QA 与平台导出。

目标用户：中小商家运营、品牌电商团队、代运营和设计审核人员。首发品类建议为素材完整的普通美妆护肤商品，扩展到家居与服饰前完成对应测评。此处是待评审选择。

产品目标：用户无需编辑 Prompt，完成上传、确认事实、生成图片包、自动修订、复核与导出。北极星指标是每周完成并导出的合格商品包数量。

已确认：电商定位、UI A 组合、蓝紫云白颜色、保留迭代循环和完整 P0—P3 路线。本文新增的数值、字段、默认包和计费规则属于可评审实现建议，确认后形成冻结基线。

### 1.1 阶段范围

| 阶段 | 包含 | 不含 |
|---|---|---|
| P0 | 点击原型、商家访谈、事实/规则建模、100 SKU 基准集与主体保护验证 | 对外商业承诺 |
| P1 MVP | 单 SKU 图片、确认事实、模板、品牌基础规则、QA、自动修订、版本、额度账本、ZIP | 视频、完整详情页、任意视角、目录批量、店铺直发 |
| P2 | 视频、分镜、结构化详情页、多平台派生、候选多参考模型 | 全自由画布、所有平台 HTML 直传 |
| P3 | 批量、团队审批、配方、反馈试验、授权品牌定制评估 | 无授权训练、保证转化提升 |

P1 默认建议图片包：1 主图、2 卖点图、2 场景图。用户可修改任务清单；必需交付物标记写入版本。首发具体平台列表与规则版本在 P0 冻结，未经维护的“通用尺寸”仅用于设计预览，不自动获得可发布结论。

## 2. 术语与角色

| 术语 | 定义 |
|---|---|
| ProductTruth | 经用户确认的商品不可变事实及证据 |
| CommerceSpec | 单次任务冻结的事实、品牌、平台、目标、创意、交付与预算快照 |
| GenerationJob | 按预算和状态机运行的生成任务 |
| AssetVersion | 不可变的素材版本与父子关系 |
| QualityReport | 对指定素材与规则快照的质检证据 |
| Recipe | 经接受的可复用品牌视觉配方 |
| 合格包 | 当前交付清单的必需项全部通过有效规则且无阻断 |

P1 账号所有者可创建、编辑、生成和导出自身项目；所有数据从首期保留 tenant_id。P3 增加管理员、编辑者、审核者和只读成员。权限由服务端验证，前端隐藏按钮不构成权限控制。

## 3. 用户故事与主流程

| 编号 | 用户故事 | 成功条件 |
|---|---|---|
| US-01 | 运营上传商品实拍图后，希望快速完成事实确认 | 不清晰项明确待确认；不虚构规格 |
| US-02 | 商家选择平台和任务后，希望看到产物及费用 | 开始前明确数量、预计额度和上限 |
| US-03 | 设计师希望只改背景并保留商品 | 锁定区域与来源可见；新版本重新 QA |
| US-04 | 运营希望知道图片为何不能导出 | 显示失败项、区域、证据和可执行动作 |
| US-05 | 商家希望恢复旧版本 | 旧版保留；按当前规则重新判断可用性 |
| US-06 | 用户取消或遇到失败，希望费用清楚 | 取消可追踪、账本一致、不重复结算 |
| US-07 | 团队希望按 SKU 批量审核 | P3 SKU 独立状态、权限与预算 |

主流程：快捷首页—新品上架包—上传与事实确认—目标/平台/品牌—清单与报价—异步生成—硬检查—视觉评审—自动修订—人工复核—导出—反馈。

人工确认商品事实是生成前的必要关口。任务失败时停留在项目中，保留已生成结果、费用和可恢复步骤；刷新页面或重新登录后可继续查看。

## 4. 信息架构与页面交互

### 4.1 首页与导航

P1 一级导航：首页、商品项目、模板、品牌资产、素材与版本、额度。P2 增加视频/详情页任务，P3 开放目录生产和数据优化。首页四任务入口中未上线能力显示“后续阶段”，不能点击后假装运行。

首页展示继续制作、最近交付、待复核、额度。空态主按钮为“创建新品上架包”，避免空白 Prompt。项目卡展示商品、平台、进度、通过/待复核/阻断数量和更新时间。

### 4.2 商品项目工作台

左侧商品素材、事实、品牌与平台；中间交付物；右侧选中素材的 QA、锁定项、修订动作；底部专业抽屉显示 Prompt、模型、事件与费用。无选中素材时右侧显示项目总览。

每张卡分开显示“生成状态”和“质量状态”。多选导出前显示可导出、阻断和未检查数量。页内批量操作只作用于所选素材，禁止默认包含隐藏筛选项。

素材详情并列或滑杆对比原图、父版本和当前版；支持查看质检区域、放大文字、回退为选用版。用户点“仅换背景”后显示将保留的主体范围与预计费用。更改角度、数量或 SKU 属于新任务或事实变更，不伪装成背景修改。

### 4.3 状态与视觉

使用 #246BCE 主行动、#6D5BD0 生成、#15803D 通过、#B45309 待复核、#DC2626 阻断、#F8FAFC 背景、#FFFFFF 卡片。主次文字 #0F172A / #64748B。中性约 80%、蓝约 12%、紫约 3%，其余不超过 5%。每个状态必须带文字/图标，错误消息可读且有下一步。

桌面优先，窄屏侧栏折为抽屉；主流程具备键盘焦点和表单错误定位。不得用装饰性生成动画掩盖排队、取消或失败状态。

## 5. P1 功能需求

### 5.1 项目、素材与事实

| 需求编号 | 行为规则 | 验收要点 |
|---|---|---|
| FR-001 | 创建项目，填写名称、SKU、品类；同租户 SKU 重复提示但不覆盖 | 项目有独立 ID 和所有者 |
| FR-002 | 上传 1—6 张 JPEG/PNG/WebP，建议每张 ≤20MB，最短边 ≥1024px | 服务端验证真实类型；低清可存但提示补图 |
| FR-003 | 提供预览、上传进度、失败重试；原始文件不可被生成结果覆盖 | 文件哈希和来源保留 |
| FR-004 | 每张参考图标注职责：主体、包装、细节、风格；风格图不作为商品事实 | 冲突参考提示用户选择 |
| FR-005 | 自动提取名称/颜色/可见文字等，标记已识别、待确认、不可读 | 未确认关键项无法开始生产 |
| FR-006 | 用户确认事实并生成 ProductTruth 版本 | 记录确认人、时间与来源 |
| FR-007 | 修改事实生成新版本，关联结果标记需复检 | 旧版任务快照不变 |

文件数量与大小是拟定限制，开发评审可按上传成本调整。不能从图片推断真实成分、认证、疗效或缺失规格；模型建议与用户确认值分开保存。

### 5.2 模板、品牌与平台

| 需求编号 | 行为规则 | 验收要点 |
|---|---|---|
| FR-010 | 模板含用途、交付清单、允许变化、输入要求、QA、推荐预算 | 不只是 Prompt 文本 |
| FR-011 | 品牌基础套件含颜色、Logo、授权字体、语气及禁用表达 | 每次任务引用套件版本 |
| FR-012 | 平台规则含来源、适用类目、版本、生效/复核日期 | 规则缺失或过期待复核 |
| FR-013 | 预览交付清单和每项比例、尺寸、格式及必需标记 | 修改清单重新报价 |
| FR-014 | 用户输入有依据的卖点、规格与价格 | 无来源内容提示补证据 |

平台规则优先级：法律及平台硬约束、商品事实、品牌约束、模板、用户创意。冲突不能靠静默覆盖解决；显示冲突和可选处理，无法满足时停止。

### 5.3 生成与自动修订

| 需求编号 | 行为规则 | 验收要点 |
|---|---|---|
| FR-020 | 开始前冻结 CommerceSpec、报价与预算 | 任务可重放其依据 |
| FR-021 | 关键包装使用真实主体合成；环境由模型生成 | 原始主体与掩码版本可追溯 |
| FR-022 | 异步任务显示排队、生成、评审、修订阶段 | 刷新后状态恢复 |
| FR-023 | 建议默认最多 3 轮含首轮，并有总费用上限 | 任一上限触达停止 |
| FR-024 | 自动修订仅针对可修复问题，优先一个关键项 | 记录保留项、变化项、原因 |
| FR-025 | 连续两轮关键问题无改善或主体不可修复则停止 | 显示原因与人工选择 |
| FR-026 | 用户可取消；已运行供应商若不能取消则本地阻止后续阶段 | 迟到结果不得恢复已取消任务 |
| FR-027 | 供应商超时/限流按受控次数重试，仍失败返回可恢复状态 | 幂等，不重复任务或收费 |
| FR-028 | 手工专业 Prompt 修改需另存版本并重新全量 QA | 不绕过事实与硬约束 |

相似度不是商品真实的充分证据。主体保护需记录区域与允许的几何/光照变换；掩码外生成、边缘融合及输出压缩后也要检查。未提供足够视角时，不承诺生成正确背面或内部结构。

### 5.4 质量报告、复核与导出

| 需求编号 | 行为规则 | 验收要点 |
|---|---|---|
| FR-030 | 检查文件、尺寸、商品、文字/Logo、视觉、品牌、风险 | 每项有 pass/fail/unknown/not_applicable |
| FR-031 | 硬失败为 blocked；无硬失败但有必要未知项为 needs_review | 总分高不覆盖硬失败 |
| FR-032 | 显示参考证据、问题区域、严重度、置信度与建议 | “不可读”不当作文字正确 |
| FR-033 | 用户可确认被标记为可人工裁决的未知项 | 记录人、理由、证据，状态带人工确认 |
| FR-034 | 商品事实和平台硬失败不允许普通用户强制变绿 | 需修复或改规则后重检 |
| FR-035 | 回退或选择历史版本不改写原文件与报告 | 当前规则有效性另行计算 |
| FR-036 | 合格包导出 ZIP、图片、manifest 和 QA 摘要 | 必需项全部通过；名称稳定 |
| FR-037 | 部分导出只含通过项并标记 partial，不计合格包 | 缺失清单明确 |
| FR-038 | 待复核/阻断可下载带水印审阅稿，不进入正式发布包 | UI 与 manifest 标记用途 |

正式导出时复核事实、规则、素材三者版本及文件哈希。若审核后发生变化，原报告仍留存但对当前导出失效，需重新检查。导出是下载文件，不代表向平台发布。

## 6. 生成状态机与质量状态机

GenerationJob：draft—validating—quoted—queued—running—evaluating—revising—evaluating，终态为 completed、limit_reached、failed、cancelled。若用户预算需额外确认，进入 awaiting_confirmation，不自动扩大预算。一个任务可有多个素材子任务，父任务汇总成功与失败项。

completed 只表示计算流程结束。质量独立为 not_checked、checking、publishable、needs_review、blocked、stale。事实或规则改变时相关结果为 stale，不能正式导出。

| 触发 | 状态动作 | 不变量 |
|---|---|---|
| 提交生成 | 原子预留预算，再入队 | 预留失败不得调供应商 |
| 重复提交 | 返回同一幂等键对应任务 | 不重复预留 |
| 质量失败可修复 | 有预算/轮数才修订 | 不覆盖历史通过版 |
| 达上限 | limit_reached | 给出最佳候选与问题，不自动标通过 |
| 取消 | 写 cancel_requested；禁止新子任务；终态 cancelled | 迟到回调只审计，不复活 |
| 超时 | 根据供应商查询与重试策略决定 | 未知调用不可盲目重复收费 |
| 人工复核 | 改复核记录、重算质量状态 | 不改机器原始证据 |

## 8. Provider Adapter 契约

Provider 不暴露给默认商家流程。统一能力：capabilities、validate、estimate、submit、poll、cancel（可选）、normalize_result。实际签名在代码评审确定，行为要求如下。

| 方法 | 必须行为 |
|---|---|
| capabilities | 声明图/视频、参考数量、掩码、尺寸、异步、取消和种子支持 |
| validate | 对不支持的约束明确拒绝，禁止静默丢弃主体保护 |
| estimate | 返回价格版本、预估成本、误差区间或上限 |
| submit | 带内部任务 ID、请求哈希与供应商幂等键（若支持） |
| poll | 区分排队、运行、成功、失败、未知，不把未知当失败重复提交 |
| cancel | 返回已取消/不能取消/已完成；系统本地停止仍生效 |
| normalize_result | 保存实际模型、用量、时延、原始请求 ID 与输出哈希 |

标准错误：INVALID_INPUT、UNSUPPORTED_CAPABILITY、RATE_LIMITED、PROVIDER_TIMEOUT、PROVIDER_ERROR、CONTENT_REJECTED、BUDGET_EXCEEDED、CANCELLED。错误日志不记录访问密钥或临时签名 URL。

P0 保留 Seedream 与基线；P1 评测 GPT Image 精修并做不超过 5% 灰度；P2 评测 FLUX 多参考及视频；P3 才评估授权品牌定制。所有系列均是候选方向，具体版本和商用条款待核验。

新增阶段使用素材准备、spec 确认、预算预留、生成、硬检查、视觉评审、修订、人工复核、导出；与原 scene_analysis、prompt_generated、image_generation、image_evaluation、prompt_revision 等阶段建立版本映射，不直接删除旧事件语义。

## 10. 额度、计费与商业化需求

价格草案：免费体验、¥59 个体商家、¥199 增长店铺、¥599 团队、企业定制。点数和权益未冻结；旧讨论的点数仅用于测算。费用遵循统一账本，不由前端余额决定能否生成。

| 编号 | 规则 | 验收 |
|---|---|---|
| BILL-01 | 开始前展示预计、最高额度、轮数与报价有效期 | 过期报价重新确认 |
| BILL-02 | 并发提交原子预留，可用余额不得为负 | 不发生超卖额度 |
| BILL-03 | 每次 capture/release/refund 有唯一操作键 | 重复回调不重复扣费 |
| BILL-04 | 供应商技术失败不重复向用户扣费；质量失败策略单独展示 | 账单可解释 |
| BILL-05 | 取消按预先确认且已发生的可计费阶段结算 | 未发生部分释放 |
| BILL-06 | 系统赠送修订次数与内部费用单列 | 不隐性扩大用户预算 |
| BILL-07 | 套餐切换、加油包、退款按服务端交易状态生效 | 不信任支付返回页的单一状态 |

计费闭环可先接测试支付与模拟额度，真实收费须完成渠道、权益、退款与条款评审。未上线的视频和团队能力不能以购买即获得方式销售。

## 11. 安全、权限、数据与非功能需求

原始图、输出、掩码和品牌资产默认私有；签名下载地址建议有效期 15 分钟。保留期建议原始/成果 90 天、审计 180 天，均为待评审参数；应支持用户导出、主动删除及备份到期策略。供应商侧留存与删除边界需如实说明。

生成授权、共享授权与训练授权分别记录。未获明确训练授权不得将客户素材用于模型训练。密钥仅放服务端安全配置，禁止进入 Prompt、浏览器或日志。

| 编号 | 指标建议与验收环境 |
|---|---|
| NFR-01 | 在约定压测环境、20 并发普通 API 下，非生成 API P95 ≤1 秒；上传与导出另测 |
| NFR-02 | P1 单包系统完成时间目标中位数 ≤10 分钟；拆分排队/模型/QA，未实测不宣传 |
| NFR-03 | 任务进程异常后可从持久状态恢复；故障注入验证无重复结算 |
| NFR-04 | 租户越权、对象存储越权、过期链接与伪造回调测试全部通过 |
| NFR-05 | 日志可按 project/job/provider request 追踪，记录成本、失败与版本 |
| NFR-06 | 备份恢复目标建议 RPO ≤24 小时、RTO ≤4 小时，试运行前演练并冻结 |
| NFR-07 | 核心任务按钮、输入与错误可用键盘完成；状态不依赖颜色 |

建议生成供应商超时、SSE 保留期、上传配额等均配置化；正式配置与告警阈值随供应商实测冻结。

## 12. P2 视频与详情页需求

| 编号 | 需求 | 验收 |
|---|---|---|
| VID-01 | 从通过图选择首帧，确认分镜、时长、比例、运动与预算 | 无有效首帧不可直接生成商品视频 |
| VID-02 | 先支持 3 秒低幅度动效，再开放 8—12 秒视频 | 时长按供应商实际支持，不伪造扩展 |
| VID-03 | 检查首中尾、场景切换、文本与风险帧；必要时加密采样或人工 | 检测不足为待复核 |
| VID-04 | 音频、音乐和人物来源可追踪 | 不默认生成已获授权人像 |
| PDP-01 | 首屏、卖点、场景、细节、规格、服务模块结构化 | 参数引用事实，不虚构认证 |
| PDP-02 | 模块重排、替换、按平台派生 | 变更只重检受影响项并全量检查关键约束 |
| PDP-03 | 导出长图/切片；适用平台可导出 HTML | 每种格式匹配平台能力 |

首帧锁定不保证每一帧商品一致，必须经过视频 QA；不把抽帧通过描述为完整视频没有任何缺陷。

## 13. P3 批量、团队与效果回流

BATCH-01：CSV/表格导入需字段映射、重复 SKU 检查、素材缺失清单和逐行验证；不合格行不拖垮整批。

BATCH-02：先生成小样预览并估价，再启动高清；批次预算和 SKU 预算双重限制；取消批次只停止未执行项，逐项结算。

TEAM-01：成员权限按品牌、项目和动作控制；审核者可驳回与批准，编辑者不得绕过配置审批；审批后修改素材使批准失效。

RECIPE-01：从已采用结果保存品牌配方，记录适用品类与授权；公共模板不得泄露客户资产。

FEEDBACK-01：记录采用、驳回、原因与人工分数；导入投放结果需授权、指标定义与来源。实验固定商品/人群等关键变量，报告相关性和不确定性。

TRAIN-01：品牌私有训练仅评估高价值、有明确素材授权的项目，记录供应商、用途、保留和撤回处理；不自动训练所有店铺素材。

## 15. 验收用例与发布门槛

| 用例 | Given / When | Then |
|---|---|---|

| AC-06 | 两个并发任务竞争最后额度 | 仅足额任务预留成功，余额不负 |
| AC-07 | 重复回调与客户端重复提交 | 只有一个任务与一次结算 |
| AC-08 | 用户取消后供应商迟到回调成功 | 不恢复运行；费用按政策结算 |
| AC-09 | SSE 断线重连或页面刷新 | 快照与去重事件恢复准确阶段 |
| AC-10 | 事实或平台规则在通过后更新 | 当前结果 stale，正式导出需复检 |
| AC-11 | 某个必需交付物失败 | 不计合格包；部分导出列出缺失 |

| AC-13 | 某平台规则缺失/过期 | 显示覆盖不足，不声称平台通过 |
| AC-14 | 恢复旧版本并导出 | 校验当前上下文；不篡改旧报告 |
| AC-15 | P2 视频中间帧商品变形 | 阻断或待复核，首帧通过不代替视频检查 |

P1 出口：所有关键验收用例通过；100 SKU 授权与样本划分完整；人工一次接受率拟定目标 ≥80%；已标注严重缺陷回归集中不得出现已知漏放；有模型/成本/时延报告。目标不是实测结果，需评审冻结后执行。

生产发布还需权限与下载安全、账本故障恢复、规则来源与有效期、客服补偿政策、实际供应商商用条件通过评审。

## 17. 需求溯源与变更规则

本 PRD 承接当前会话的产品定位、UI 原型选择、差异化、模型路线及两份正式文档要求；内部来源为现有三份规划文档和项目记忆。原有接口来自此前仓库审阅，本文接口与字段为待实现契约。

与升级方案一致的固定决策：快捷创意工厂首页、商品项目工作台核心页、团队目录控制台；ProductTruth/CommerceSpec/Commerce QA；锁商品生环境；按任务路由；P0—P3 双路线对齐。模型后缀、实时价格、平台规则和竞品功能均未在本轮重新核验，不以历史描述作为事实。

需求变更需记录版本、需求编号、理由、范围、费用与迁移影响。事实、规则、任务快照和素材版本不原位覆盖。本轮仅产出方案与 PRD，应用代码、外部服务、Git 提交和推送均未执行。

# 千图百炼：制作体验与绿色界面优化方案

状态：讨论稿，未开发。日期：2026-10-28。

## 1. 摘要

面向没有专职设计师的小商家和品牌主理人，优化首次制作、指定图片修改与已满意内容保留、商品及品牌复用；以用户认可的绿色 HTML 演示作为视觉方向，重新组织正式产品的页面。

本次只形成方案，不修改业务代码，不更新线上演示。目标是保留正式产品的完整能力，降低用户的操作和理解成本。绿色 HTML 的本地模拟排版不能代替正式产品的真实生成、账户、结算与检查。

## 2. 参与角色

| 角色 | 职责 |
| --- | --- |
| 产品负责人：用户本人 | 确认目标人群、交付要求和收费规则 |
| 产品与设计 | 确认主流程、页面原型、异常提示和绿色视觉规范 |
| 开发 | 基于已有账户、商品事实、品牌版本、任务、结算和复核能力增量实现 |
| 验收 | 使用真实商品及对照样本验证流程、修改范围、版本恢复和费用 |
| 内测商家 | 判断图是否愿意使用、修改是否省事、第二次制作是否更快 |

具体人员与排期尚未指定，不据此虚构团队配置。

## 3. 背景与现状

当前工作区基于 `qiantubailian-commerce`，应用版本 0.23.0，正式界面以橙色为主；用户更喜欢独立 HTML 演示的低饱和绿色、留白、卡片和左右分区。

项目已有商品项目与素材、事实版本、品牌套件、冻结配置、报价、生产任务、质量检查、复核和导出基础。不能把已有版本机制等同于新需求已实现：例如工作台当前的修改入口回到配置，不等同于可圈选局部修改的编辑器。

当前真实模型效果与 OCR 仍需外部验收。支付保持关闭，尚无商户条件。对外承诺不得用本地模拟流程或内部测试替代真实服务验收。

问题：

1. 初次用户需要理解项目、商品事实、生产配置、报价和复核等多个概念。
2. 一张图不满意时，需要明确只影响哪张图、改哪些内容、保留哪些结果。
3. 已确认的商品规格和品牌要求，应在后续制作中复用，减少重复输入。
4. 现有布局偏管理工作台，主任务与高级信息同时出现，用户不喜欢当前橙色视觉。

## 4. 目标与成功标准

目标：更容易完成第一套图；修改时减少返工；同一商品第二次制作明显更省事。

以下为待验证的目标，不是当前已经达到的数据。第一轮内测完成后，应根据基线调整。

| 指标 | 建议目标与测量口径 |
| --- | --- |
| 首次制作配置 | 上传前有效会话开始至确认生成，不含排队与模型等待；可用素材、信息明确时争取 3 分钟内完成 |
| 首次流程完成 | 5 位目标商家中至少 4 位无需口头指导即可提交任务；这只验证早期可用性，不代表市场结论 |
| 同商品复用 | 相较其第一次制作，第二次确认配置时间至少减少 50%，分别记录输入与模型等待 |
| 修改隔离 | 修改卖点图时，其他已选用图片及其版本不被改写；所有验收用例必须通过 |
| 收费透明 | 提交前展示本次最多预留/消耗额度，实际变动可追溯；重复请求、重复下载不重复扣费 |
| 视觉一致 | 首页、商品页、工作台、品牌页、额度页及弹窗遵循同一视觉规范 |

生成成功、检查通过、用户满意和实际采用分别记录，不能互相代替。漂亮界面不能掩盖图片不可用。

## 5. 目标用户与范围

优先用户：经营少量 SKU、有持续上新需求、无专职设计师的小商家或小品牌主理人。

优先任务：以已有实拍图制作一套商品主图、卖点图和场景图；节日或渠道变化时复用商品与品牌信息。

第一阶段不扩展视频、服装试穿、完整 Photoshop 式画布、复杂团队审批或自动学习训练系统。现有团队/版本能力可以保留，但不成为首次制作必经步骤。

## 6. 用户价值

| 用户需要 | 对应设计 |
| --- | --- |
| 不想学习复杂系统 | 一个连续页面完成上传、信息确认、风格与交付选择 |
| 一张不满意，不想整套重来 | 选定图片修改，保留其他交付物；始终能比较和恢复旧版本 |
| 不想再次解释规格和品牌 | 商品档案、品牌档案和历史视觉配置可复用 |
| 担心商品与中文文字被改错 | 关键事实确认、文字层编辑、主体保护与检查仍保留 |
| 不清楚要花多少额度 | 每次生成前展示范围、预估、预留和扣费规则 |

竞争差异是待验证的“少返工、少重复填写、整套更一致”，不能宣传为已经优于竞品的效果结论。

## 7. 解决方案

### 7.1 简化首次制作

主路径：进入制作 → 上传商品 → 核对必要信息 → 选风格与交付 → 看清报价后提交 → 查看结果 → 处理有问题的部分 → 下载。

在一个制作页面中使用渐进展开的三步，不连续弹出多个窗口：

1. **放入商品**：拖入/选择实拍图，预览主体；缺少图片时提供明确上传按钮。项目名称可由文件名预填后编辑，项目在后台建立。SKU、专业参数不要求第一次立即填写。已有登录机制保留；认证中断后返回当前步骤，不能无提示丢失输入。
2. **确认信息**：只显示本次交付需要的名称、关键规格和卖点。OCR 可用时给出候选并标记来源，不能直接当作已确认事实；不可用时允许手动填写。未核实的关键规格不编造，缺少卖点时可改选不含该卖点的交付模板。事实约束由所选交付真正需要的内容决定，不能靠虚假默认值绕过。
3. **选择效果**：默认推荐一组风格；首屏展示 3 个明确方向，其他模板放入更多。默认套图为主图、卖点图、场景图，允许调整交付项。已有品牌可直接选择；没有品牌时不强迫先建品牌库，可以不加 Logo 并采用临时配色。最后在同页展示交付数量、本次最多使用额度及按钮。

主按钮示例：`生成 3 张图片 · 最多使用 3 点`，实际数值必须来自报价接口。实际费用未知或服务不可用时，不给出假的成功预估。

“高级设置”折叠收纳平台规则详情、文字排版、主体框修正及专业参数。正常路径不要求理解“冻结规格”；系统内部仍保存本次使用的商品与品牌快照。

异常：图片格式/尺寸不合适就地提示；素材或卖点改变时刷新报价与配置；提交重复点击不得创建重复任务；离开后可以从任务记录继续；修改配置不暗中改写运行中的任务。

### 7.2 局部修改：分三种承诺

| 修改类型 | 第一阶段行为 | 保留范围 |
| --- | --- | --- |
| 文案、文字位置、品牌色等排版修改 | 优先编辑独立文字/排版层并重新合成，不重新调用生成模型 | 已有背景和商品素材不重生成；重新检查文字及排版 |
| 只重做一张图的背景/构图 | 选中主图、卖点图或场景图中的一张，展示修改范围后另建版本 | 其他图片保持原文件与当前选用版本；选中图片按实际模型能力处理 |
| 圈选区域重绘 | 后续能力，必须有支持区域编辑的真实模型，并完成区域外变化验收 | 没有掩码能力时不展示“其余像素完全不变”的承诺 |

第一阶段先实现前两项，不用提示词加“其余不变”冒充真正区域锁定。

结果卡片提供：放大、修改这张、加入交付包/选用、历史版本。用户选中图片后进入修改面板，给出“改文字”“调排版”“重做背景”等明确选项，辅助输入一句修改要求；不把只有自由提示词的文本框当作完整修改能力。

示例：三张图中主图与场景图满意，只修改卖点图的文案。系统保留原图与其他两张结果，生成卖点图的新排版版本；失败时仍能查看旧版本，不能把整套结果置空。

保留与合格分别表示：“保留这张”仅表达用户选择，不能覆盖质检失败。不可发布的图片仍需显示阻断原因，不能因用户满意就自动通过。

版本规则：

- 修改总是产生新版本，原版本不覆盖。
- 新结果产生后展示前后对比，用户决定选用哪个版本；不能刚完成就悄悄替换已选交付。
- 改一张图时，整包交付可引用其他图片原来的已选版本，不要求把全部重新生产。
- 修改操作与所依赖的商品事实、品牌、文字层和来源版本绑定；原任务运行中修改信息，不改变它的既定输入。
- 商品关键事实改变后，相关旧图显示“基于旧信息制作”，提示检查或重做；保留记录，不静默删除旧图。

**建议计费规则，需作为产品决定确认：**

- 修改文字/基础排版、选择或恢复已有版本、重复下载，不额外消耗生图额度；可以有合理的操作频率限制。
- 用户主动重生成一张图，按新增合格成品计费，提交前展示报价；原已付费图片不再次计费。
- 系统认定的失败不按成品收费；待复核继续遵循可解释的预留状态。主观不满意不自动等同客观失败，不承诺无限免费重生成。
- 一个新结果只结算一次；用户恢复旧版本不重复收费，也不自动退款已经成功交付的新版本。
- 原内容付费状态、水印预览和正式下载权限仍保留；免费文字编辑不能绕过未付费底图的下载限制。
- 自动纠错涉及的次数与额度，沿用任务事先声明的上限并单独说明，不能静默追加。

### 7.3 复用商品与品牌

把复用拆成三个入口：

**同商品再制作**：从商品卡片选择“再做一套”，带入当前确认的商品信息、原图和品牌；用户只需要改主题、渠道或交付项。显示“沿用哪些信息”和一键编辑入口。

**换新商品，沿用风格**：从历史作品选择“用这个风格做新品”。带入品牌、模板、配色与排版方向，但清空旧商品的容量、尺寸、成分、型号、功效和素材。不能因为外观相似就继承事实。

**品牌资料**：集中保存 Logo、品牌色、已确认的字体与使用状态、默认视觉方向。支持多个品牌和明确选择当前品牌，不把店铺所有商品自动绑定到最近编辑的品牌。

用户编辑品牌时，提示影响未来制作，旧结果保持其制作时的快照。需要按新品牌重做的图片单独确认；不能一次修改品牌色导致所有历史图片和进行中任务改变。

复用信息必须隔离账户与工作区。默认只带入用户可访问的素材与品牌。删除或替换源图片时，保留已有交付所需的依赖或明确提示影响，不能产生打不开的历史记录。

### 7.4 绿色界面与页面结构

设计方向：以用户认可的 HTML 演示为参考，采用低饱和绿色、暖白背景、留白、清晰卡片和左右分区；复用其视觉语言，不照搬其精简功能和营销布局。

建议视觉值：主色 `#365F49`，背景 `#F7F8F5`，主文字 `#263A32`，次文字 `#6D786F`，分割线 `#DFE5DC`。最终在实际字体、字号和交互状态下检查对比度。焦点、选中、不可用和错误状态需要单独设计。

绿色用于主操作和选中态；警告仍可使用琥珀色，失败使用红色。每个状态同时配文字或图标，不能把所有状态变成绿色以营造“通过”的假象。

主导航建议：`首页 / 我的商品 / 我的作品 / 品牌与模板`；右上角常驻额度、帮助、账户。任务记录和历史版本跟随商品或作品呈现，避免独立堆积大量入口。

| 页面 | 布局与主要操作 |
| --- | --- |
| 首页 | 大上传/开始制作入口、继续制作、少量风格样例；新用户显示引导，老用户优先最近商品与任务 |
| 我的商品 | 商品封面卡片、名称、上次制作状态；操作为继续制作、再做一套、编辑商品信息 |
| 制作工作台 | 桌面左侧约 300–340px 的步骤与设置面板，右侧为宽预览区；避免复杂表格与多个常驻侧栏 |
| 修改工作台 | 当前图片大预览、明确修改范围和前后对比；其他交付物以缩略图切换，历史版本按需打开 |
| 我的作品 | 按商品/任务组织套图，展示版本与交付状态，可筛选，不能让未通过结果看起来已经正式交付 |
| 品牌与模板 | 品牌档案和风格选择相互关联；默认提供少量可理解方向，更多模板按需展开 |
| 额度与订单 | 同一绿色视觉；报价、有效期、明细和禁用收款状态清楚显示 |

桌面预览可以显示三张结果，但文字编辑或精细比较时放大当前一张，不能把图片和工具全部压进窄卡片。窄屏改为纵向步骤与预览，当前主要按钮易于找到；不强行保留三列布局。

统一覆盖登录、空状态、加载、上传失败、任务重试、复核和额度弹窗，不只改首页。说明性样例与真实用户任务分开标注，不显示虚假的项目数量和已通过状态。

### 7.5 必须保留的产品状态

- 草稿与已提交任务可区分；输入和任务进度可恢复。
- 排队、生成中、待复核、被阻断、已交付有明确文案。
- 用户喜欢的结果与系统检查通过分别表达。
- 模型/OCR/支付未配置时如实提示可用范围。
- 尚未完成的检查不记为通过；未解决的商品事实问题不能靠 UI 简化消失。

### 7.6 验收场景

1. 新用户只填真正必要的信息即可创建默认三张图任务，价格与实际选项一致。
2. 无 OCR 时可以手动录入，不出现伪造提取结果；必要事实缺失时给出可理解的处理办法。
3. 品牌可选；没有 Logo 不要求伪造；字体不可用时明确替代方案。
4. 只改卖点图文字，另外两张图片与当前选用版本保持不变，未调用生成模型，不新增生图费用。
5. 单独重做背景时只创建该交付物的新版本；旧版保留；失败后其余已交付内容仍可用。
6. 用户选择“保留”不能覆盖硬失败；新版本重新进行与修改相关的检查。
7. 恢复旧版本、重复请求和重复导出不重复收费。
8. 同商品再制作自动带入确认信息；换新商品沿用风格不带入旧规格和素材。
9. 修改品牌不改写历史图片、旧任务输入或其他租户数据。
10. 刷新、返回、退出再登录后能恢复可恢复的任务/草稿，不把不可恢复的本地文件伪装为已保存。
11. 电脑和手机可完成上传、确认、生成、改单张、复核和下载，没有横向挤压或隐藏的关键按钮。
12. 模拟演示与正式生产的状态可辨认，报价、模型和支付能力不被假数据冒充。

### 7.7 尚待验证的假设

- 用户是否更喜欢固定三张套图，还是只做一张主图。
- 哪三种风格能覆盖目标类目的首批需求。
- 用户是否接受新增合格图片消耗额度、基础文字排版免费这一规则。
- 模型是否支持可靠的背景修改，原图局部合成在真实光照下是否自然。
- 简化后是否仍能获得足够准确的事实输入，而不是只把错误留到后面。

## 8. 交付顺序与范围

不在未评估真实模型和现有依赖前承诺固定天数。建议按可独立验收的模块推进：

1. **流程与视觉原型**：先确定首页、首次制作、结果修改三个关键页面；明确正常路径与失败状态。
2. **首次制作简化＋绿色基础界面**：整合已有输入与配置能力，形成一条完整默认路径；同步必要报价、复核与登录状态。
3. **商品与品牌复用**：完善同商品、新商品和品牌版本的不同继承规则，验证第二次制作是否更快。
4. **改单张与基础文字排版修改**：明确版本来源、修改范围、检查、交付包引用及幂等计费；这是独立业务模块，不是单纯换 UI。
5. **全站界面统一与端到端验收**：补齐所有页面和异常路径，在授权真实模型上验证效果，再安排商家试用。

真正的圈选重绘后置，取决于模型能力与区域外保留测试。没有通过外部效果验收前，不把前述模块完成解释为“产品生图质量已领先”。

开发阶段可沿用用户既定流程：每模块开发、自检、修复、提交与推送后自动进入下一模块；全部完成后整体端到端验收。该流程是后续实施约束，本轮未执行任何开发、提交、推送或部署。

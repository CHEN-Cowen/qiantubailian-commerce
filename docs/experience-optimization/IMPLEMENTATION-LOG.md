## 模块 03：商品与品牌复用

### 实际实现

1. 向导支持三种复用入口（`qb:open-wizard`）：E1 同一商品再做一套（`reuse`，沿用项目、素材、事实与 spec 冻结快照，可改后重确认）；E2 用此风格制作新品（`style`，只预选模板/品牌）；E3 品牌入口（`brand`，只预选品牌）。
2. 复用边界在代码里写死：`style`/`brand` 只预选模板与品牌，商品事实与素材一律重新确认；`reuse` 沿用的是 spec **冻结快照**，不会随品牌最新版本漂移。
3. 预选项只有在目录中仍存在时才套用（模板或品牌被删除则回落为空），避免复用出无效配置。
4. E1 复用后仍需在第二步重新核对关键事实，历史填写不会被当成"这次也成立"。

### 测试证据

- `test/ui-contract.js` 新增 41 行：复用入口、E1/E2/E3 文案、复用不改事实的提示文案。

## 模块 04：文字排版修改与版本选择

### 实际实现

1. 新增 `src/text-edits.mjs`：文字层校验（可编辑文案、包装关键文字与 Logo 只读、未知层、重复编辑、字数上限），问题码如 `PACKAGING_TEXT_READONLY`、`TEXT_LAYER_MISSING`。
2. `src/jobs.mjs` 版本模型：`run.versions[]` 只增不改，每次修改产生新版本并带独立质量报告；`active_version_id` 单独切换，历史版本可恢复。
3. 新版本复用同一底图（`overlay_base_hash` 与来源版本一致），本地重新合成文字层，**不重新调用生成模型**，因此不产生额度流水。
4. 新版本若质检不可发布（如 OCR 硬失败），只登记历史，不进入 active；复核不能放行硬失败项。
5. 接口：`GET /api/runs/:id/deliverables/:did/text-layers`、`POST .../text-edits`、`POST /api/runs/:id/versions/:vid/activate`；全部按租户鉴权，跨租户 404。

## 模块 05：指定图片重生成与按张结算

### 实际实现

1. `POST /api/runs/:id/regenerate`：只重做指定交付物，单张独立报价（`pricing.onlyDeliverableIds`），按成品张数预留额度。
2. 幂等：同一 `Idempotency-Key` 返回同一子任务，不重复扣点；进行中重复请求返回 409。
3. 子任务产物登记回源任务（`adopted_from.run_id`），版本只增；未复核的新图不自动替换 active，其他交付物的选用版本不受影响。
4. 生成失败释放预留额度；终态后可再次发起；跨租户 404，不泄漏对象是否存在。

### 测试证据

- 新增 `test/m14.js`（450 行，3 组用例）：成功路径（其它交付物不变、旧结果保留、重启后复核恰好 capture 1 点、人工选用、导出新版本）；失败与错误路径（失败释放、legacy 409、失效版本 404、跨租户 404）；进行中互斥与 versions 只增。
- 全量测试通过。

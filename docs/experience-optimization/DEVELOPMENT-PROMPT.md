## B. 产品目标与本轮边界

目标用户是没有专职设计师、经营少量 SKU 且需要持续上新的小商家和品牌主理人。

本轮必须完整完成四项：

1. 简化首次制作。
2. 修改指定图片或文字排版，保留满意结果和旧版本。
3. 复用商品与品牌信息。
4. 参考绿色演示，重新组织正式产品的布局和视觉。

以真实商品输入、减少重复填写、降低返工和明确费用为核心。第一阶段围绕商品主图、卖点图和场景图，不顺带扩展视频、服装试穿、复杂审批、完整专业画布或自动学习训练。

在已有项目增量实现，复用账户、授权、事实版本、品牌、任务、额度、质检与导出。保留必要校验和审计信息，将复杂概念隐藏在正常任务后面，而不是取消业务保护。

绿色 HTML 是界面与交互参考，不能把其本地模拟排版当作正式模型能力，也不能用简化静态页面替换业务系统。

## C. 首次制作完整需求

### C1. 一页三步

用户在一个连续页面完成“上传商品 → 确认必要信息 → 风格与交付”，减少弹窗切换。首次制作不要求理解项目、事实版本、冻结规格等内部术语。

**上传商品**：支持拖拽与选择、上传状态、预览和清晰错误；文件格式、大小与解码限制以服务端实际配置为准。自动建立商品草稿，名称可从文件名预填并编辑。SKU/内部编号不成为首轮必填；若现有数据要求，可使用明确的内部标识，不能伪造商品事实。源图和草稿的保存状态必须真实。

保留现有认证机制。认证完成后回到当前步骤，避免丢失表单。浏览器尚未上传的文件与服务端已保存素材分别表示；刷新无法恢复的内容要如实提示。

**确认信息**：仅展示所选交付真正需要的商品名称、关键规格、卖点。OCR 可用时给出候选、来源与待确认状态；无 OCR 时可手动填，不生成假识别结果。关键事实需要用户确认，不能编造容量、尺寸、材质、成分、功效或品牌。事实不足时说明缺什么，允许选择不依赖该事实的交付；不能靠占位卖点绕过约束。

**风格与交付**：首屏提供约 3 个可理解的推荐风格，更多模板按需展开；默认主图、卖点图、场景图三项，允许调整。选择已有品牌即可带入；无品牌/Logo 时允许不加 Logo 开始，避免强制建库。

生成按钮附近显示交付项、张数、最多预留/消耗额度和计价说明，例如“生成 3 张图片 · 最多使用 3 点”，数值必须来自真实报价，不能硬编码与实际不符的价格。

### C2. 高级设置与状态

主体框修正、文字位置、规则详情和专业参数放入高级设置，必要时再显示。内部保留本次事实、品牌、模板及配置快照。

改变素材、交付或影响价格的配置时刷新报价；报价失效、余额不足、服务不可用时提供可操作提示。提交防重复，生成后显示真实的排队、处理中、失败、待复核、受阻或可交付状态，不虚构进度百分比。

草稿可保存与继续；已提交任务的输入不会被之后的表单编辑悄悄改变。网络中断、刷新和返回时尽量恢复，恢复边界明确。

## D. 修改与满意内容保留

### D1. 第一阶段必须实现的两类修改

**文字与基础排版**：编辑已有基础能力覆盖的文案、位置、字号、品牌色等。优先通过独立文字/排版层重新合成，保留背景和商品内容，不重新调用生成模型。文案需来自允许的已确认事实；涉及事实变化时引导先更新确认，而不是允许随意生成不实卖点。

每次重新合成仍检查受影响的文字、尺寸和排版。图像可能因编码或文字覆盖产生变化，不能无验证承诺输出全部像素一致；应保证底图来源未重新生成。

**只重做指定图片**：用户选择某一张交付图重做背景或受支持的构图，其他交付物保持原文件和当前选用版本。不能通过重新运行整套任务冒充单张修改。

例：主图、场景图满意，只重做卖点图，就只创建卖点图的新版本，整包引用其他两张的原有效版本。

结果卡片包含放大、修改这张、选用/保留、历史版本。修改面板提供改文字、调排版、重做背景等明确操作，再辅以自由描述；开始前说明影响哪张图、改什么、保留什么及费用。

### D2. 版本、检查与能力边界

- 每次修改生成新版本，旧版本不可覆盖；失败后旧图可用，其他结果不变。
- 新版与旧版可对比，明确当前选用版本；新结果不自动替换用户已经选好的交付内容。
- 支持恢复旧版及按交付物组合选用版本，导出引用正确且属于当前账户的结果。
- 用户保留/满意与系统检查通过分别记录。被保留但检查失败的图仍提示问题，不能用“满意”覆盖硬失败。
- 修改记录绑定来源图片、事实、品牌、配置与操作范围。并发修改或页面中的旧信息不能覆盖更新后的选用结果。
- 商品关键事实变化后，识别受影响结果并标记基于旧信息，提示重新检查/制作，保留历史记录。
- 导出前检查当前选择的全部版本，处理待复核、失效和权限问题，不能导出混入失效版本的“正式成品包”。
- 模型缺少相关能力时就地说明或禁用。真正圈选区域重绘后置；不通过一句“其余不变”冒充像素级局部锁定，不虚报掩码支持。

### D3. 计价与结算规则

将以下规则作为本轮产品要求实施，并与原有权益机制兼容：

1. 基础文字/排版修改不额外消耗生图额度；允许合理的频率与资源限制。
2. 选用/恢复已有版本、重复下载不重复扣费。
3. 用户主动重生成一张图片时，预先报价并只为本次新结果预留额度；按新增合格成品结算，旧付费图不重复收费。
4. 同一结果只结算一次。重复请求、回调、重试、刷新、恢复和导出不能重复结算；余额不能为负，跨账户不得消费或读取。
5. 系统判定失败不按成品收费；待复核有明确预留状态；取消、失败、重启和超时按可追溯规则释放或保留，不丢失权益。
6. 恢复旧版本不自动退款已经成功交付的新版本。主观不喜欢不等于客观失败，不承诺无限免费重生成。
7. 系统自动修复的次数、预算和用户主动修改分别记录；沿用事先说明的额度上限，不能静默追加。
8. 免费排版不改变底图的付费与下载权限；未付费/未通过底图的衍生版本仍保留相应预览水印、访问和交付限制。
9. 新编辑版本关联源图的权益，保证“免费修改”不重复收费，也不会成为免费获取付费原图的通道。

## E. 商品与品牌复用

### E1. 同商品再做一套

从商品卡片或作品进入，带入已确认商品信息、可用原图、品牌与适用配置。用户主要调整主题、渠道或交付，清楚看到沿用了哪些资料并可编辑。必要字段变化后重新确认相关内容，而不是强制从零填写。

### E2. 用此风格制作新品

从模板或历史作品进入，沿用配色、排版方向、模板和可访问的品牌资料。清空旧商品的素材、容量、型号、尺寸、成分、功效、卖点及确认状态，重新确认新品信息。不能将外观相似视为相同事实。

### E3. 品牌资料

保存 Logo、品牌色、字体及使用状态、默认风格；支持多品牌和明确选择。没有 Logo 不创建假 Logo；字体不可用时提供可解释的替代方案，不冒充已获商用许可。

品牌更新默认影响未来制作。历史结果与进行中任务保留原有快照；按新品牌重做由用户明确发起。避免全局改色修改历史作品。

素材替换、删除和权限变化要处理依赖，不能产生打不开的历史交付。复用必须按账户、工作区和实际权限检查，不跨租户读取品牌或图片。

## F. 绿色界面与布局

### F1. 视觉规范

参考仓库绿色 HTML 的低饱和绿色、暖白背景、留白、卡片和清晰左右分区。保留正式产品完整业务，而不是照抄静态演示的数据和页面数量。

建议基础色：主色 `#365F49`、背景 `#F7F8F5`、主文字 `#263A32`、次文字 `#6D786F`、分割线 `#DFE5DC`。在实际字体和状态下验证可读性，统一按钮、表单、间距、圆角和标题层级。

绿色表示主操作和选中；警告可用琥珀色，失败用红色；用文字/图标辅助表达，检查未通过不画成绿色成功。设计加载、不可用、焦点、选中、错误及长文本状态，支持键盘和正确表单标签。

### F2. 页面组织

建议导航为“首页 / 我的商品 / 我的作品 / 品牌与模板”，右上角额度、帮助与账户常驻。任务、历史版本与商品/作品关联，避免为每个内部模块都设独立一级入口。

| 页面 | 必须实现的布局与行为 |
| --- | --- |
| 首页 | 突出上传/开始制作、继续制作、少量风格参考；新用户引导，老用户优先最近任务；统计和列表使用当前工作区真实数据 |
| 我的商品 | 商品封面、名称与任务状态；继续制作、再做一套、编辑信息；空状态能直接开始 |
| 制作工作台 | 桌面左侧约 300–340px 步骤和设置，右侧宽预览；高级设置折叠，不常驻多个窄侧栏 |
| 修改工作台 | 当前图片大预览、范围说明、前后对比、可选历史版本；其他交付物缩略切换 |
| 我的作品 | 按商品/任务展示套图，清楚标识选用、检查、交付和历史版本；支持正确下载 |
| 品牌与模板 | 品牌档案与少量易理解风格入口；沿用风格与沿用商品分别表达 |
| 额度/订单/认证 | 与主界面统一，报价、有效期、明细、登录返回和支付关闭状态准确 |

支持桌面和手机。窄屏转为纵向设置与预览，确保主按钮、价格、错误、复核与下载可访问；不把三张图片和全部编辑工具挤到同一窄行。避免弹窗溢出、固定导航遮挡、横向滚动和图片变形。

覆盖首页之外的登录、全部相关弹窗、空状态、错误、任务、复核与额度页；仅将橙色替换成绿色不算完成。

## G. 业务和外部服务边界

保留服务器会话、CSRF、租户授权、素材鉴权、报价校验、事实校验、任务恢复和真实质检；页面简化不能关闭这些保护。

默认保持真实支付关闭。用户只有个人微信收款、尚无营业执照和商户号；本轮不把个人收款码包装成自动到账，也不为验收发起真实付款。

模型、OCR 未配置时如实说明，支持授权范围内的内部模拟测试；模拟结果不能冒充真实生成。素材须有使用依据，测试不上传真实客户数据、会话、密钥或 `.env`。

当前单进程存储边界保持，除非实现本轮必需，不顺带重构为分布式架构。

## H. 必须遵守的模块执行闭环

**每个模块执行顺序固定：开发 → 模块自测 → 修复 → 复测通过 → 审查本模块差异 → 独立提交 → 推送远端并确认成功 → 自动开始下一模块。**

不逐模块询问是否继续。进度说明不等于等待批准。常规设计、字段与实现选择自行作出并记录依据；只有真实缺少必要权限/凭据、重大无法判断的业务冲突才提出具体问题，同时完成不受影响的工作。

具体规则：

- 每模块开始记录目标、涉及能力、验收条件，结束更新执行记录。
- 自测采用有意义的业务与交互检查，风险逻辑有回归测试；不为纯颜色变化堆砌镜像测试。
- 发现模块内问题先修复并重新检查，相关必需检查未通过不能标记完成。
- 每模块独立提交，必要时包含紧密相关的修复提交；不能所有模块完成后才一次性提交。
- 推送成功后核对远端分支包含该模块提交，才通过模块门槛并进入下一模块。
- 推送网络失败先合理重试。权限或远端状态无法解决时保留本地成果、记录阻碍，暂停后续模块推进；不能把本地提交说成已推送。
- 远端有其他新提交时在保留已有修改的前提下正常整合、解决冲突并复测；不使用 force push、破坏性清理或覆盖用户代码。
- 当前工作区有既有修复时，先逐项核对，相关且已授权的纳入模块 00；无关修改保持原状。暂存明确文件，禁止盲目 `git add .` 夹带资料和密钥。
- 维护 `docs/experience-optimization/IMPLEMENTATION-LOG.md`，记录模块、实现、实际测试、结果、未验证项、提交与推送状态。提交编号可在下一条记录补入，避免循环修改只为给文件写入它自己的提交号。

## I. 模块拆分与验收门槛

### 模块 00：基线核验与必要阻断修复

检查当前分支、远端、未提交修改、启动、测试脚本与规范；输出本轮基线和需求映射。按 `BASELINE.md` 复核历史前端初始化、真实数据、图片内容/权限、成品计价等与本轮相关的阻断缺陷，不假设本地历史修复已在远端。

在隔离环境完成可运行基线，修复阻碍后续开发的内部问题。记录已有失败与外部待办，不把已知内部缺陷当作无关理由跳过。自测后单独提交并推送。

### 模块 01：绿色视觉与正式页面骨架

建立可复用的颜色、按钮、输入框、状态、卡片、导航和布局；完成首页、工作台、修改视图的关键结构。保留可用业务入口，不能用占位界面覆盖原流程。

验收：首页至工作台可导航；真实/示例内容可辨认；桌面与窄屏无明显遮挡；正常、加载、错误与不可用状态清楚。自测后提交推送，自动继续。

### 模块 02：首次制作三步流程

完成 C 节全部要求，接通真实素材、事实、品牌、配置、报价与任务。高级配置收纳但业务检查保留。

验收：正常上传到生成可走通；无 OCR 可手填；必要事实不完整有明确反馈；报价随选项变化；登录返回、刷新和重复点击安全；无可用模型时如实报告。自测后提交推送。

### 模块 03：商品与品牌复用

完成 E 节全部要求，包括同商品再制作、新商品沿风格和品牌快照。

验收：同商品少填信息；新品无旧规格和旧确认污染；改品牌不改旧任务；权限隔离和素材依赖正确。自测后提交推送。

### 模块 04：文字排版修改与版本选择

完成免费基础文字/排版修改、来源绑定、前后对比、版本选用/恢复、关联检查与底图权益继承。

验收：未重新调用生图模型；未改交付物和底图来源保持；历史可恢复；未通过不能被满意标记放行；免费修改不绕过付费下载。自测后提交推送。

### 模块 05：指定图片重生成与结算

实现仅重做选定交付物、报价预留、成功一次结算、失败/取消/超时/重启处理；交付包引用各自选用的有效版本。

验收：改卖点图时主图/场景图文件及选用版本不变；旧结果保留；重复请求/刷新/导出无重复扣费；实际能力不支持的修改明确提示；跨租户和失效版本被拒绝。自测后提交推送。

### 模块 06：全站一致性与移动端

统一商品、作品、品牌模板、认证、额度订单、弹窗与复核页面；补齐空状态、错误恢复、长内容、键盘和移动端体验。

验收：桌面及手机都可完成完整主路径；没有残留的断链、旧样式遮挡或假状态；浏览器能看到真实功能。自测后提交推送。

### 模块 07：整体端到端自测、修复与最终推送

所有模块完成后进行全流程自测，不以逐模块通过代替整体测试。按下一节执行；发现问题就修复，复测关联场景并重新跑必要整体检查。通过后提交并推送最终修复、验收记录与文档更新；若无需修复，也提交并推送真实验收记录。检查远端最终提交和工作区状态。

## J. 最终端到端验收清单

在隔离数据与至少两个账户/工作区中测试，使用当前项目声明的运行环境、安装方式和测试脚本，记录实际命令、运行时间与结果。已有脚本如有变动，应解释并运行真实等价检查。

1. 新用户认证 → 上传 → 核对必要信息 → 选品牌/不选品牌 → 风格和交付 → 报价 → 提交。
2. 正常任务、排队、失败、取消、余额不足、报价失效和网络中断有正确状态与恢复。
3. 图片预览、真实检查、待复核、阻断、通过、正式下载和 ZIP 全部符合权限及结算。
4. 改卖点图文字或排版，背景未重新生成、无新增生图消费，其他两图及选用版本不变。
5. 重做一张图只生成新单张版本；计价明确、旧图保留、版本切换和整包下载引用正确。
6. 同结果重复请求、通知、刷新、重试、导出不重复扣费；失败/取消/重启的预留与释放正确。
7. 恢复旧版不重复收费；未付费底图的衍生版本不能越权下载；未通过图不能因选用而放行。
8. 同商品再做一套可复用；沿用风格做新品不带旧素材、旧规格和确认状态。
9. 更新品牌或事实不改写运行任务和历史结果；受影响图的失效提示与后续处理正确。
10. 账户之间不能读取、修改、复用、计费或导出对方商品、品牌、素材和版本。
11. 刷新、关闭重开、退出再登录可恢复相应任务/草稿；未保存文件不假装已保存。
12. 桌面和手机能完成制作、改单张、复核与下载；检查关键页面截图、长文字、无图、错误与加载状态。
13. 本轮修改相关自动测试与项目必需全量检查通过；不得删除测试、放宽检查、吞异常或隐藏报错来伪造通过。

测试证据应能对应场景；纯模拟测试只证明内部流程，不证明真实模型质量、OCR 准确率、支付退款或平台审核。

有授权真实模型时，再使用同条件合法样本检查商品轮廓、图案、文字、颜色、数量与实际光照。缺少服务或凭据时完成内部测试，标出外部未验收，不把已知内部失败包装成“外部限制”。

## K. 完成定义与最终交付

只有需求已实现、内部必要自测及端到端检查通过、问题已修复、模块提交与最终记录已推送并确认远端包含对应提交，才能报告开发完成。外部效果未验收须单列，不能宣称生产效果或收费资格已经成立。

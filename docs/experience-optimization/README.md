# 千图百炼：制作体验与绿色界面优化接手包

本目录提供给后续开发软件。2026-10-28 本次只新增需求、执行提示词、基线说明和视觉参考，未实施业务代码修改或线上更新。

## 阅读顺序

1. [完整执行提示词](DEVELOPMENT-PROMPT.md)：完整优化要求、模块划分、自测、提交推送与最终端到端验收。
2. [产品方案](PRD.md)：用户目标、功能细节、状态与验收场景。
3. [基线与能力边界](BASELINE.md)：重要，说明本地修复与远端代码不一致的问题。
4. [绿色演示 HTML](reference/green-demo.html) 和 [工作台截图](reference/green-demo-desktop.png)：视觉与交互参考。HTML 下载后可离线打开，GitHub 文件页只展示源码。
5. [本地修复参考](LOCAL-REPAIR-REFERENCE.md)：既往修复方向及其当时的测试记录，不是当前远端代码验收结果。

需求冲突时按后续用户明确指令、`DEVELOPMENT-PROMPT.md`、`PRD.md` 的顺序处理。历史报告中的“已修复”不替代对当前代码的检查。

主流程：上传 → 确认必要信息 → 风格/交付/报价 → 生成 → 单张修改与复核 → 下载；再次制作复用同商品与品牌。

执行规则：每模块开发 → 自测 → 修复与复测 → 单独提交 → 推送确认 → 自动下一模块。全部模块完成后整体端到端自测，修复到内部检查通过，再提交推送最终修复及验收记录。

当前计划代码分支为 `feat/commerce-commercialization`。本次文档上传不合并 `master`。完整提示词和视觉快照均保存在仓库内，后续软件不依赖在线演示持续可访问。

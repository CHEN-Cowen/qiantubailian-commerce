## 2. 本机小规模压测（非生产容量结论）

在同一台本机、进程内启动服务，执行以下探测：

| 场景 | p50 | p95 | 最大 | 错误 |
|---|---|---|---|---|
| `GET /healthz` 顺序 200 次 | 6.0 ms | 8.5 ms | 11.3 ms | 0 |
| `GET /api/projects` 并发 100 | 354.9 ms | 419.8 ms | 443.9 ms | 0 |
| `POST /api/projects` 顺序 50 次 | 15.2 ms | 17.9 ms | 43.5 ms | 0 |

观察：

- 存储读是串行队列，100 并发列表请求被排队，p95 约 420 ms；这是当前 JSON 持久化实现的已知特性，不是故障。
- `/healthz` 不经过 API 计数管道，因此 `/api/metrics` 的 `http.total` 只统计 `/api/*`，本次为 150（100 次列表 + 50 次创建）。
- 该结果只用于验证「不会在常规请求下崩溃或明显退化」，不能作为生产容量或 SLA 依据。

## 4. M12 实现与验收要点

- 采用只落在当前选用、报告 `publishable` 且 `validity=current` 的版本；blocked、needs_review、stale 与未结束任务都不能采用。驳回必须带登记理由，同一版本以最新一条反馈为准。
- 效果数据导入必须 `authorized: true` 且给出来源与授权引用；未授权为 403；逐行校验空 SKU、负数指标、点击大于曝光、订单大于点击、批内重复；全坏行返回 422，不落库；好行与坏行分开记录。
- 实验只比较 control/variant 的 CTR、CVR、单均成本与采用率；样本不足标 `insufficient_sample`；样本足够也只声明观测差异，`statistical_significance=not_computed`，不宣称因果。
- 套餐全部 `billable: false`、`price_cents: null`。无支付 Provider 时下单 409；模拟 Provider 只能创建演示订单并发放内部演示额度，重复结算 409；真实退款在通道未接入时 409。
- 指标只输出聚合计数与任务分布，不含素材、事实与提示词；跨租户只统计本租户。
- 备份按租户裁剪，记录数据哈希、各表记录数与 blob 引用哈希；恢复前校验清单、租户、数据哈希、记录数与引用文件，任一不符拒绝恢复；恢复只替换本租户数据，其他租户与备份历史保留。

## 6. 必须如实声明的限制

- 生成图来自确定性模拟 Provider，不是真实模型商品图；M06 的真实 Adapter 契约存在，但没有真实密钥与真实模型验收。
- 额度、报价、套餐均为内部演示额度，不代表真实货币、发票或可计费权益。
- 没有真实支付与退款通道；所有"订单/结算"都明确标记为演示订单。
- 没有真实授权评测集、第二模型 Adapter 与盲评，M09 未完成真实模型基准与灰度验收。
- Provider 不支持视频，M10 只完成计划、帧级检查与阻断路径，没有已生成的视频文件。
- OCR 与视觉评审模型未接入，相应检查只报 unknown；平台规则来源未核验，不能声称平台合规。
- 像素级检查只对 PNG 生效，JPEG 只校验签名、头部与尺寸。
- 成员、角色与租户由请求头与本地记录决定，没有真实身份认证、单点登录或细粒度数据授权。
- 效果数据只能由商家自行授权导入，没有对接外部平台 API；实验结论不构成投放保证。
- 服务只允许绑定 loopback，没有生产部署、反向代理、TLS、密钥管理与容量验证。
- 未运行项：真实模型基准、真实支付/退款、真实平台数据回传、真实视频生成、生产规模性能与故障演练。
